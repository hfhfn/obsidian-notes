## 一、为什么企业 AI 缺一个「大脑」

### 四个现实判断（EP1 开场）

| 判断 | 含义 |
|---|---|
| **企业 AI 转型失败率 80%**（麦肯锡） | 问题不在模型能力，而在缺少让模型理解业务的知识底座 |
| **按 Token 收费 = 按 CPU 收费** | 大模型厂商按 Token 计费的本质是 IT 成本，而非业务价值；如果业务收益不能明显高于 Token + 算力延迟成本，商业闭环在财务上不成立 |
| **FDE 团队 = 药厂组建医生团队** | 大模型厂商组建 FDE 深入企业一线，表面帮客户找场景，实际是找高消耗场景锁死迁移成本；服务行业必须 vendor agnostic |
| **Palantir 卖的不是 API** | 它卖的是本体化的行业知识操作系统：本体层管理企业数据语义，LLM 层负责自然语言理解，中间通过「语义网关」双向转换 |

> **问题不在于模型不行。缺的是一层让模型真正理解你业务的知识底座——本体论。**

### 2500 年极速通关

| 阶段 | 事件 | 意义 |
|---|---|---|
| 前 350 年 | **亚里士多德范畴论** | 把世界万物分成十个范畴：实体、数量、性质、关系等。人类第一次系统性地用统一结构描述世界 |
| 1950s | **符号主义先驱** | McCarthy 与 Minsky 在知识表示领域奠基，试图让机器像人一样「理解」概念，为符号 AI 奠定基础 |
| 80–90s | **知识工程兴起** | 专家系统需要形式化知识表示，推动知识工程成为独立学科。知识需要被编码成机器可读的格式 |

### 物理学类比：大模型 = 万有引力，本体 = 强相互作用

| 大模型 | 本体 |
|---|---|
| 无所不在 | 固定领域内精确度拉满 |
| 任何两个概念都能关联 | 确定性、可靠性极高 |
| 广度覆盖、灵活生成 | 把「原子核」绑在一起 |
| 但不够精确、可能幻觉 | 你的业务就是那个原子核 |

### 本体的五要素积木

| 要素 | 说明 | 例子 |
|---|---|---|
| **实体 Entity** | 世界的计算抽象，本体构建的基本对象 | 客户、订单、合同 |
| **类与实例 Class & Instance** | 概念层次结构；类定义共性，实例是类的具体化 | 「客户」是类，「张三」是实例 |
| **属性 Property** | 实体的特征描述，连接实体与值 | 张三的年龄、身高、职业 |
| **关系 Relation** | 实体间的语义连接，构建知识网络的核心 | 张三就职于某公司 |
| **公理 Axiom** | 领域约束与推理规则 | 若 A 是 B 的父亲，B 是 C 的父亲，则 A 是 C 的祖父 |

> [!abstract] 定义
> **本体论 = 领域共识的形式化知识规范。**
> 三大核心特征：**明确的 Explicit · 形式化的 Formal · 共享的 Shared**。
> 本质价值：隐性知识 → 显性化，显性知识 → 结构化，结构知识 → 可推理化。

## 二、大模型 × 本体：四种协同方式

| 大模型擅长 | 大模型短板 | 本体擅长 | 本体局限 |
|---|---|---|---|
| 广度覆盖 | 黑盒，难以解释 | 精确一致 | 符号鸿沟 |
| 灵活生成 | 幻觉，编造事实 | 可解释、可审计 | 构建成本高 |
| 上下文理解 | 知识更新困难 | 逻辑推理 100% 可验证 | 难处理模糊语言 |
| 模糊语言处理 | 缺乏领域确定性 | 因果关系明确 | 开放世界适应性差 |

### 四种协同方式

| # | 方式 | 做法 |
|---|---|---|
| ① | **语义对齐** | 把本体的实体/关系编码成向量，与大模型已有的向量空间对齐，让模型「认识」你的业务概念 |
| ② | **约束生成** | 大模型生成结果后，用本体/知识图谱做验证和过滤；输出必须在知识图谱范围内，否则打回重来。等于给大模型加了一个「知识过滤器」。**规则变化时只需更新本体，模型不用动；可插拔，最易落地** |
| ③ | **推理增强** | 把本体的因果关系、推理规则直接嵌入推理过程。大模型负责理解模糊输入，本体负责精确推导。**规则（显式泛化）+ 直觉（隐式推理）= 可信且灵活的 AI** |
| ④ | **反哺构建** | 反过来用大模型辅助生成本体：以前全靠领域专家手工，现在让大模型打草稿、专家校验。这是评估驱动设计（EDD）——大模型时代本体工程的核心范式转变 |

> 协同闭环：**对齐 → 约束 → 推理 → 构建 → 再对齐**

### 三种集成框架

| 框架 | 特点 | 适用 |
|---|---|---|
| **松耦合** | 知识过滤器模式；不改模型权重，即插即用 | 大多数企业起步选择 |
| **紧耦合** | 训练时注入本体，知识内化；推理更自然 | 需微调能力 |
| **混合集成** | 数据 + 模型 + 应用多层；灵活、可针对性优化 | 复杂企业级应用；Palantir AIP 模式 |

| 场景 | 提升 |
|---|---|
| ChatBI SQL 准确率 | **+10%** |
| 图谱辅助标注 | **+7%** |
| 医疗诊断准确性 | **+18%** |

## 三、从数据中台到智能中台：补三层能力（EP2）

### 现有数仓：AI 为什么看不懂

大多数企业的数据中台停留在「符号层」，最多到「指代层」，第三层「解释层」几乎空白：

| 层 | 例子 | AI 需要什么 |
|---|---|---|
| **符号层** | `gross_margin_rate` 只是个字段名 | 知道它是一串字符 |
| **指代层** | 这个符号指「毛利率」，口径是（营收−成本）/营收 | 知道它代表什么 |
| **解释层** | 毛利率下降意味着什么？沿哪些维度下钻？什么阈值算异常？ | 能推理 |

> [!important] 核心判断
> **AI 缺的不是数据，是让 AI 理解数据的语义层、操作数据的工具层、记住经验的记忆层。**
> 不是推翻重来，是在现有 ODS / DWD / DWS / ADS 之上加装三层。

---

### 第一层：语义层——7+1 规范体系

语义层不是一个单一的「字典」，而是一套 **7+1** 的规范体系。每一维都让 AI 对业务的理解更深一层：

| # | 规范 | 内容 | 关键点 |
|---|---|---|---|
| 1 | **实体 Entity** | 客户、订单、产品、供应商、合同 | 唯一标识、属性定义、生命周期状态；要包含业务含义、所有者、变更规则 |
| 2 | **关系 Relation** | 客户→下单→订单；供应商→提供→SKU | 不只是外键：有方向、有基数、有时间窗口 |
| 3 | **事件 Event** | 促销启动、供应商涨价、竞品补贴 | 有发生时间、影响范围、因果链。指标告诉你「降了」，事件告诉你「为什么降」 |
| 4 | **规则 Rule** | 毛利率低于 30% 预警、战略客户折扣 | AI 行为的护栏；没有显式规则，建议可能违反业务策略 |
| 5 | **指标 Metric** | 计算公式、口径版本、数据源、刷新频率、可下钻维度、正常范围 | 不只是数字定义，而是完整指标语义 |
| 6 | **词表 Glossary** | 华北区 = 北区 = NorthChinaRegion；GMV = 成交总额 | NL→SQL 的第一道翻译关 |
| 7 | **模型 Model** | 零售「人-货-场」、供应链「采-产-销」 | 让 AI 理解行业思维框架，是行业推理的前置知识 |
| +1 | **治理引擎 Governance** | 谁定义的、何时更新、版本冲突、废弃口径 | **没有治理引擎，语义层就是一次性工程** |

#### NL → SQL 的三条技术路径

| 路径 | 准确率 | 风险 / 说明 |
|---|---|---|
| **NL → SQL** | 50–70% | LLM 直接把自然语言翻译成 SQL；简单场景可以，复杂场景翻车：口径歧义、表关联错误、过滤条件遗漏 |
| **NL → SQL + RAG** | 70–90% | 加了检索增强，能查到表结构和字段注释；但注释质量参差，复杂多表关联依然困难 |
| **NL → DSL → SQL** | **98%+** | 先把自然语言翻译成领域语义语言（DSL），DSL 再确定性生成 SQL；语义层做最难的翻译，SQL 生成变成模板渲染 |

> [!tip] dbt Labs 基准数据
> 有完整 Semantic Layer 时，NL→DSL→SQL 准确率可达 **98%+**；没有语义层的 NL→SQL，在 JOIN 超过 3 张表时准确率骤降至 **50% 以下**。
> 这不是模型选型问题，是**语义资产积累问题**。

### 第二层：工具层——让 AI 动手

> AI 的能力上限，取决于它接了多少工具。语义层让 AI「看懂」，工具层让 AI「动手」。

#### MCP：AI 的 USB 接口

- **是什么**：Anthropic 开源的标准协议，让任何 AI 模型能标准化地接入任何工具/数据源
- **怎么工作**：一个 MCP Server 暴露一组能力（查指标、查事件、查知识库），AI 通过 MCP Client 按需调用
- **核心优势**：写一次工具接口，所有模型都能用；换模型不用改工具层

#### 毛利率归因至少需要三种工具

| 工具 | 作用 | 走哪层 |
|---|---|---|
| **指标查询** | 查毛利率的值、同环比、按维度下钻 | 语义层 DSL，确定性查询 |
| **事件查询** | 查时间窗口内的业务事件：促销、涨价、竞品动作 | 事件是归因的线索 |
| **知识检索** | 查非结构化知识：市场报告、运营文档、历史分析 | RAG 支撑深度推理 |

> [!warning] 权限不是可选项
> 工具层必须内置权限控制。不同角色看到的数据粒度不同：VP 看大区汇总，BU Head 看品类明细，一线看 SKU 级别。**权限是生产级必须。**

### 第三层：记忆层——本体就是 Agent 的长期记忆

Agent 没有记忆，每次对话都是「失忆重来」。记忆层让 AI 积累经验、沉淀知识、越用越准：

| 记忆类型 | 内容 | 例子 |
|---|---|---|
| **业务规则** | 毛利率低于 30% 预警、战略客户折扣豁免、铜料长单比例不低于 45% | AI 需要记住，不能每次重新问 |
| **领域知识图谱** | 实体关系网络：铜 → 家电 → 华北线下，供应商 → 原材料 → 产品线 | AI 跳转推理的「地图」 |
| **历史分析记忆** | 上次分析毛利率下降时，用户纠正了铜料对冲比例是 45% 不是 30% | 纠正要记住，下次不再犯同样错误 |

| 没有记忆的 Agent | 有记忆的 Agent |
|---|---|
| 每次对话从零开始 | 记住历史对话和纠正 |
| 重复犯相同的错误 | 从错误中学习迭代 |
| 不知道业务规则和约束 | 自动应用业务规则 |
| 无法积累经验 | 分析越来越精准 |
| 输出质量不稳定 | 输出质量持续提升 |

> [!important] 三层的关系
> **语义层是静态知识（什么是什么），工具层是动态能力（能做什么），记忆层是进化能力（学到了什么）。**
> 三层叠加，Agent 才能从「能用」→「好用」→「越来越好用」。

### 之上的运行时：Harness

```
Agent = Model + Harness
```

| 组件 | 作用 |
|---|---|
| **Agent Loop 核心** | 思考 → 行动 → 观察 → 再思考的自主循环；Loop 的质量决定 Agent 的「智商」 |
| **权限控制 / 安全** | 谁能看什么数据、调什么工具、执行什么操作；生产环境必须有细粒度权限，否则数据安全就是裸奔 |
| **上下文管理效率** | Token 有限，如何在窗口内放入最相关的信息，决定 Agent 的「效率」和「准确度」 |
| **Hooks 系统扩展** | 在关键节点插入钩子：发送前审核、工具调用前鉴权、输出后记录；让 Harness 具备可观测性和可扩展性 |

> **Model 是通用智能（别人家的），Harness 是你自己的业务封装。**

### 贯穿所有层：治理全景（三层双路径）

| 治理层 | 维度 | 目标 | 工具 |
|---|---|---|---|
| **顶层治理** | 语义治理 | 确保数据语义、全公司视图一致 | Ontology 语义层 |
| | 领域治理 | 聚焦领域视图，事件产生即赋值 | ECA 事件感知层 |
| | 规则治理 | 消除规则模糊性，流程合规可配置 | ECA 规则决策层 |
| **决策治理** | 多源治理 | 消除多源孤立，建立统一数据视图 | Ontology 动力层 |
| | 决策治理 | 业务 AI 决策，智能推理不出错 | Ontology 决策层 |
| | 执行治理 | 消除执行天花板，动作结果可溯源 | ECA 自动执行层 |
| **执行治理** | 规则/约束治理 | 确保业务行为合规，规避风险 | ECA 约束引擎 |
| | 治理/监控治理 | 治理可视化、可控、可度量 | 可视化看板 + 监控告警 |

> **Ontology = 大脑（认知地图），ECA = 手脚（自动执行）。** 前半段让系统「懂业务」，后半段让系统「会干活」。

## 四、落地路线图：四步走

| 步骤 | 做什么 | 时间 |
|---|---|---|
| ① **指标语义化** | 从最核心的 20–50 个指标开始，补全计算公式、口径版本、维度定义、业务解释。不贪多，先把最常用的做透 | 2–4 周 |
| ② **查询接口化** | 用 MCP 标准把指标查询、事件查询、知识检索封装成工具。先做「只读」，让 AI 能查但不能改 | — |
| ③ **试点场景落地** | 选一个高频、低风险的分析场景跑通全链路，例如「月度毛利率归因」 | — |
| ④ **逐步加厚** | 场景验证成功后，扩展更多指标、工具、记忆。语义栈越厚，AI 越准 | 持续 |

### 三个核心判断

1. **数据中台不需要推翻重来。** ODS/DWD/DWS/ADS 的分层投资都是有效的，你需要的是在上面加装三层能力。
2. **语义层的厚度决定 AI 的准确率。** 50% 和 98% 的差距就在语义层——这不是模型选型问题，是语义资产积累问题。
3. **Agent = Model + Harness。** Model 会不断贬值（更便宜、更强），Harness 的价值只会升值——因为它封装的是你独有的业务知识、工具能力和经验积累。

> **模型会贬值，语义资产只会升值。**

## 五、11 步归因全景：每一层在做什么

问题：「Q3 毛利率掉了 3.1 个点，怎么回事？」

| # | 步骤 | 做什么 | 依赖的层 |
|---|---|---|---|
| 1 | **意图解析** | 识别为「指标归因」任务，拆解指标、时间窗口、异常幅度、对比基准 | Harness · Agent Loop |
| 2 | **指标语义层拆解** | 查毛利率完整定义：公式、口径版本、数据源、可下钻维度 | 语义层 · 指标 |
| 3 | **维度下钻（三刀切）** | 按地区 → 华北降 2.1 点；按品类 → 家电降 1.8 点；按渠道 → 线下降 1.8 点 | 工具层 · 指标查询 + 语义层 · 维度 |
| 4 | **跳出指标 → 本体层查询** | 沿关系网络跳转：SKU 核心材料 = 铜 → 供应商 SupplierX → 上游 MineZ；同时发现促销强度「高」、竞品有补贴 | 记忆层 · 知识图谱 + 语义层 · 关系 |
| 5 | **事件层验证** | 铜价 Q3 环比涨 12%；BrandM 启动以旧换新补贴；华北促销密度同比涨 40% | 工具层 · 事件查询 + 语义层 · 事件 |
| 6 | **量化回填** | 铜价传导 −0.9 点、促销折让 −1.8 点、竞品补贴 −0.4 点，合计 −3.1 点，闭合 | 工具层 · 指标查询 + 语义层 · 指标 |
| 7 | **规则安检** | 检查数据权限、合规约束、运营规则；毛利率 35.1% 高于 30% 预警线；促销收紧需区分战略/非战略客户 | 记忆层 · 业务规则 + Harness · 权限 |
| 8 | **锚定文档** | 把市场报告锚定到 `material:copper`，监测报告锚定到 `brand_M` 实体，多跳推理可追溯原始证据 | 工具层 · 知识检索 + 语义层 · 锚定 |
| 9 | **归并输出** | 三层结构：定性（原因是什么）+ 量化（影响多大）+ 建议（怎么办） | Harness · 上下文管理 |
| 10 | **会话反馈** | 记录对话焦点：毛利率 → 华北 → 家电 → 线下；用户纠正（铜料对冲比例 45%）回流更新 | 记忆层 · 历史记忆 + Harness · Hooks |
| 11 | **治理闭环** | 把「卡点」结构化记录：语义歧义、数据缺失、规则冲突；分类 → 分配 owner → 修复 → 验证 → 沉淀 | 语义层 · 治理引擎 + 记忆层 · 沉淀 |

> [!success] 关键结论
> **11 步里，没有一步只靠 Model。** 每一步都依赖 Harness 的某个组件。这就是为什么说「Agent = Model + Harness」。

### 只有大模型 vs 完整语义栈

| 只有大模型 | 完整语义栈 |
|---|---|
| 「可能是成本上升」 | 精确归因到渠道级 |
| 「可能是收入下降」 | 跨领域关系推理 |
| 「建议进一步分析」 | 事件验证 + 量化回填 |
| = 正确废话 | = 可执行建议 |

## 六、8 层语义栈（EP1 的全局图）

| 层 | 组成 | 回答什么 |
|---|---|---|
| **表层（Agent 直接消费）** | 会话与反馈 · 意图与任务 · 规则与约束 · 能力与权限 | Agent 怎么听、怎么问、什么能干、能扮演什么角色 |
| **中层（世界理解）** | 本体语义（静态地图）· 指标语义（量化快照）· 过程与事件语义（动态流动） | 世界长什么样、现在怎么样、事情怎么发生 |
| **底层（桥梁）** | 锚定语义 | 把 SOP、业务描述、设计文档挂到本体节点上，让推理可追溯 |
| **贯穿层** | 治理 | 语义统一、指标版本、事件完整、规则合规 |

> 仅有本体的 Agent = **有地图没仪表盘的飞行员**：知道山川河流在哪，但不知道飞多高、油剩多少、风向如何。本体、指标体系、大模型，三者缺一不可。

## 七、一页速查

| 概念 | 一句话 |
|---|---|
| **本体** | 领域共识的形式化知识规范（Explicit / Formal / Shared） |
| **语义层** | 让 AI「看懂」：7+1 规范（实体/关系/事件/规则/指标/词表/模型 + 治理） |
| **工具层** | 让 AI「动手」：MCP 把查指标、查事件、查知识封装成工具 |
| **记忆层** | 让 AI「越用越准」：业务规则 + 知识图谱 + 历史纠正 |
| **Harness** | Agent 的运行时：Loop + 权限 + 上下文 + Hooks |
| **NL→DSL→SQL** | 语义层做翻译，SQL 生成变模板，准确率 98%+ |
| **Ontology + ECA** | 大脑 + 手脚：懂业务 + 会干活 |
| **治理** | 横切所有层的暗线；没有治理，语义栈就是一次性的 |

> [!quote] 三句金句
> 1. **模型会贬值，语义资产只会升值。**
> 2. **企业 AI 的瓶颈不在模型能力，在语义栈的厚度。**
> 3. **谁先把业务知识变成可计算、可推理、可共享的本体资产，谁就拿到了 AI 时代的真正门票。**
