## 0. 一句话答案（面试省流版）

回答 Harness 五要素时，**千万不要答 Memory、Planning**——那是 Agent 的**能力维度**，不是 Harness 的**工程要素**。

真正的五要素：**Context（上下文）、Tools（工具调用）、Guardrails（约束）、Evaluation（验证）、Recovery（纠错）**。

- **前两项**（Context + Tools）管"能不能做事"
- **后三项**（Guardrails + Evaluation + Recovery）管"能不能做错事、做错了怎么办"

> 面试金句：*"Memory 最终是以上下文的形式进模型的，落脚点是 Context；Planning 只是一种计划模式。两者都是能力维度，真正的工程要素是另外那三项约束、验证、纠错。"*

## 1. 面试避坑：为什么答 Memory / Planning 会出局

面试官问："Harness 的五要素是什么？除了 Context 和 Tool Use，你还知道哪些？"

- 如果回答"还有 Memory 和 Planning"，**恭喜你出门右拐回家等通知**。
- **原因**：Memory 和 Planning 是 Agent 的**能力维度**，不是 Harness 的**工程要素**。
  - Memory → 以上下文形式进模型 → 落脚点是 **Context**
  - Planning → 只是一种计划模式 → 落脚点是**工作模式**
- 真正让**生产级 Agent** 稳定运行的是另外三项约束：**Guardrails、Evaluation、Recovery**。

视频结构预告：
1. Harness 是什么？五要素分别是什么？
2. 各要素各管什么事、解决了什么问题？
3. 工程上怎么落地？生产级代码怎么实现？

资料来源：**VILA-Lab Claude Code 源码分析论文、李博杰《深入理解 AI Agent》**。

## 2. 核心定义：Agent = Model + Harness

- **Harness 本义**：马具（缰绳、马鞍）。
- 大模型像**爆发力极强的野马**——能力强大，但需要可控的运行环境；套上缰绳马鞍，才能在受控轨道上全速奔跑。
- **Agent = Model + Harness**
  - **Model**：负责推理
  - **Harness**：模型之外 Agent 的**运行治理环境**

![五要素总览](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/01-%E4%BA%94%E8%A6%81%E7%B4%A0%E6%80%BB%E8%A7%88.webp)

## 3. 五要素总览

| 要素 | 英文 | 核心问题 | 类别 |
|---|---|---|---|
| 上下文 | **Context** | 感知什么 | 能力赋予 |
| 工具调用 | **Tools** | 如何行动 | 能力赋予 |
| 约束 | **Guardrails** | 能否执行 | 工程护栏 |
| 验证 | **Evaluation** | 是否做对 | 工程护栏 |
| 纠错 | **Recovery** | 失败怎么办 | 工程护栏 |

> 让 Agent **能做事、做对事**。前两项赋予能力，后三项是不出事的护栏。

## 4. 逐项拆解五要素

### 4.1 Context（上下文管理）：让模型看到高质量信息

![Context上下文](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/02-Context%E4%B8%8A%E4%B8%8B%E6%96%87.webp)

- 负责 **System Prompt、历史会话、Skill 及工具执行结果**的组装与状态维护。
- 核心目标：让模型每次决策时看到的都是**高质量信息**。

### 4.2 Tools（工具调用）：把行动接到外部环境

![Tools工具](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/03-Tools%E5%B7%A5%E5%85%B7.webp)

- 解决"模型如何与外部环境交互"的问题。
- 职责：**工具注册、定义 JSON Schema、MCP 协议适配、具体执行**。

### 4.3 Guardrails（约束）：行动先过权限检查

![Guardrails约束](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/04-Guardrails%E7%BA%A6%E6%9D%9F.webp)

- 限制模型**不能做什么**：删文件、跑脚本、访问敏感文件等**高危操作必须拦截**，防止模型失控、越权、产生不可逆破坏。
- 高危操作必须触发 **HITL（人机协同审批）**。
- **判定逻辑必须硬编码在 Harness 层**——不能交给极易受**提示词注入**影响的模型自身。

### 4.4 Evaluation（验证）：用外部证据检验结果

![Evaluation验证](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/05-Evaluation%E9%AA%8C%E8%AF%81.webp)

- 解决"如何客观判断模型做对了没有"。
- 不能盲目信任模型自述"任务已完成"。
- 必须引入**外部的确定性反馈**。

### 4.5 Recovery（纠错）：出错之后怎么恢复

![Recovery纠错](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/06-Recovery%E7%BA%A0%E9%94%99.webp)

- 带着报错信息让模型**反思后重试**。
- 连续失败时触发**熔断**，可打断任务交给人工处理。

## 5. 工程落地 ①：Context 管理（Claude Code 五阶段）

上下文越来越长，发送给模型之前**依次经过五个阶段**：

![五大阶段](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/07-%E4%BA%94%E5%A4%A7%E9%98%B6%E6%AE%B5.webp)

1. **预算削减**：给单条消息里的工具结果设大小上限。
2. **历史裁剪**：把过旧、无用的对话直接删掉（确定性规则）。
3. **微压缩**：专门清理较旧的工具结果。
4. **上下文折叠**：做读取时的虚拟投影。
5. **自动压缩**：让 LLM 生成摘要（**唯一调用模型的阶段**）。

![历史裁剪](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/08-%E5%8E%86%E5%8F%B2%E8%A3%81%E5%89%AA.webp)

- **为什么不在第 1 步就让模型总结？** 因为 LLM 生成摘要**要花 Token，而且是有损压缩**。
- **原则：能用规则解决的就不要碰模型**——前四个阶段是确定性规则，只有最后才调 LLM。

> 预防的输出问题：工具**输出直接把上下文撑爆**。比如 `git log` 输出几万行，全塞进上下文，系统指令和会话历史的权重就被噪音淹没。**超长输出必须有截断机制**，保证工具结果不会把关键信息挤出上下文。

## 6. 工程落地 ②③④：Guardrails / Evaluation / Recovery 的隔离设计

### 6.1 Guardrails：独立分类器（Claude Code 七种权限模式）

![Guardrails隔离](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/09-Guardrails%E9%9A%94%E7%A6%BB.webp)

- Auto 模式下启动一个**独立 Sonnet 分类器**，判定每次工具调用是否危险。
- 分类器**只看工具名和参数**，**看不到主模型的推理文本**。
- 原因：主模型可能在推理里写"这个删除是用户明确要求的"，从而**诱导分类器放行**——所以隔离视图，不被主模型推理干扰。

### 6.2 Evaluation：只认客观物证

![Evaluation物证](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/10-Evaluation%E7%89%A9%E8%AF%81.webp)

- 判断依据来自**执行结果**，而不是模型的"确信程度"。
- 编译器的**状态码**、**语法树**差异、**单元测试断言**……模型说"代码已修复"没用，**必须跑一遍全量测试才算**。
- 因为模型自我评估可能被**提示词注入操纵**，也可能**产生幻觉**。
- Claude Code 有 **27 个钩子事件（Hooks）**可插装验证逻辑，例如工具执行完先经过 **PostToolUse** 钩子才允许收尾。

### 6.3 Recovery：先让模型看到真相（清洗报错堆栈）

![Recovery清洗](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/11-Recovery%E6%B8%85%E6%B4%97.webp)

> 模型最容易犯的错：**不是不会做，是错了之后还想接着做**。

- Recovery 第一件事：**让模型必须看到真相**。
- Claude Code 会把报错堆栈**清洗一遍再回填上下文**——只留能定位问题的信息（如 `TypeError: value is undefined at parseInput(input.ts:42)`），去掉重复日志、无关输出等噪音。
- 真到 Token 上限：**逐级放宽限制重试，每轮最多三次**；上下文吃紧先做一次上下文折叠再压缩；仍不行就**终止**。

## 7. 源码结论：生产级 Agent 工程占多少

![984工程占比](/AI%E5%A4%A7%E6%A8%A1%E5%9E%8B/Agent/Harness%E4%BA%94%E8%A6%81%E7%B4%A0%E5%9B%BE%E6%96%87%E7%AC%94%E8%AE%B0/%E9%85%8D%E5%9B%BE/12-984%E5%B7%A5%E7%A8%8B%E5%8D%A0%E6%AF%94.webp)

- **VILA-Lab 分析 Claude Code v2.1.88 源码快照**得出暴论：
  - **98.4%** 的代码在做 **Harness**（模型之外的运行治理）
  - **1.6%** 是 **AI 决策逻辑**（模型推理与决策）
- 结论：生产级 Agent 的核心，**在模型之外的运行治理环境**。

## 10. 幻灯片 OCR 原文速查（VILA-Lab / 图片页面全文字）

- **五要素定位**：能力赋予 → Context 组织每次决策所需信息、Tools 连接外部环境并执行行动；工程护栏 → Guardrails 按权限与策略限制行动、Evaluation 用测试与证据检验结果、Recovery 处理失败（重试或交人工）。
- **上下文五阶段**：预算削减（限制工具结果大小）→ 历史裁剪（删过旧对话）→ 微压缩（清理旧工具结果）→ 上下文折叠（读取时虚拟投影）→ 自动压缩（LLM 生成摘要，消耗 Token、内容有损）。
- **Guardrails Auto 模式**：独立 Sonnet 分类器只看工具名和参数，不读主模型推理文本（防"这个删除是用户明确要求的"诱导）。高危操作触发 HITL 审批，判定逻辑硬编码在 Harness 层。
- **Evaluation 物证**：编译器状态码、语法树差异、单元测试断言；"代码已修复"须跑全量测试验收，判断依据来自执行结果而非模型确信程度。
- **Recovery 清洗**：报错堆栈清洗后回填上下文，只留可定位信息（如 `TypeError: value is undefined at parseInput(input.ts:42)`），去噪音；Token 爆时逐级放宽重试（每轮≤3 次），再不行终止。
- **工程占比**：Claude Code v2.1.88 源码快照——98.4% 代码做 Harness，1.6% 是 AI 决策逻辑。
