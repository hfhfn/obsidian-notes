# 🗣 项目叙事与简历表述（怎么把"做的事"讲成故事、写成实的）

> [!abstract] 说明
> 解决两个常卡的点：**①"项目中遇到什么困难"不知道从哪说；②简历/口述里全是概念词，不够真实。** 给框架 + 可直接套用的清单与改写示例。

---

## 1. 「项目中遇到的困难」从哪入手——顺着整个业务流程脑暴

> 别凭空想"难不难"，**从业务闭环走一遍，能想到问题、想到方案，全都是"困难"**。

**走一遍闭环找困难（每个环节自问）**
- **工具调用**：工具怎么调用；调用出问题怎么排查/解决？
- **Skill**：有没有用 skill？技能怎么调用/加载？
- **MCP**：如果用 MCP，有没有遇到问题（配置/鉴权/网络/超时）？
- **输出不稳定（JSON）**：模型输出乱格式怎么办 → **function call + pydantic + 提示词约束 + 错误重试**（即错误反馈重试，见 05·Q3）。
- **模型**：用的什么模型？**具体型号**要能报（见 Agent深挖·§7）。
- **并发**：并发怎么样？协程/单进程/限流怎么撑（见 并发限流·03）。
- **小模型**：有没有用小模型/蒸馏做快路径（见 真题复盘·Q16）。
- **兜底**：调用出错怎么兜底（超时/降级/缓存/重试退避）。
- **记忆/上下文**：记忆上下文怎么持久化（见 Agent深挖·§6）。
- **容错**：**各个节点出错怎么回退 / 容错**（Agent 多节点：失败重试、回退到上一状态、checkpoint 断点续跑）。

**心法（面试能直接说的立场）**
> "问题 + 解决方案，就是遇到的困难。我不是没困难，而是每个节点都想好了怎么解——工具失败重试、JSON 不稳四件套、并发协程+限流、记忆落 PG、节点回退容错。"

---

## 2. 单个困难怎么讲（STAR 变形）
**背景 → 卡点（具体、真实）→ 我的解（方案/取舍/为什么这么选）→ 结果（量化）**
- 别只喊"难"：**讲"怎么想、怎么解、为什么换选型"**，面试官要的是你的解决问题过程，不是诉苦。
- 有取舍更好："我们最初 X，但遇到 Y，改用 Z（代价是…）"——体现权衡。

---

## 3. 简历/口述表述具体化：概念 → 业务（动词+数据+手段+结果）

> 把"基于 XX 构建 XX"这类**概念句**，改写成"**做了什么动作 + 用了什么数据结构 + 多少量 + 按什么维护/实现 + 可量化结果**"，才像真做过。

**改写法**：`动词` + `数据规模` + `具体技术手段` + `元数据/引用维护方式` + `（结果量化）`

**示例转换**
| 概念表述（虚） | 业务表述（实） |
|---------------|---------------|
| "基于 Milvus 构建电商业务向量知识库" | 将 **N 个文本 Chunk 的 embedding 写入 Milvus**，并按**文档/页码维护元数据过滤与引用定位能力** |
| "做了 RAG / 检索优化" | 对 PDF/Excel 做**图文表分块**，异构块带 `(type,page,索引)` 元数据；混合召回 `dense+sparse` + **RRF 融合** + Rerank，**Recall@K 由 60%→78%** |
| "搭了 Agent" | 用 **LangGraph** 编排多步 Agent，意图识别→工具/MCP 路由→function-call 结构化输出，含 JSON 四件套兜底与 **Postgres checkpoint** 记忆持久化 |
| "用协程做高并发" | 单进程协程支撑 **1w~10w QPS**，LLM 走异步、同步函数按 IO/CPU 分流线程/进程池，DB 连接池满足并发 |

**原则（能背）**
> 动词开头 + 数字（N/百万/几 w QPS）+ 技术手段名 + 元数据/机制 + 可量化结果；**少形容词（强/高效），多数据与机制**。简历里每一条都按这个扫一遍替换。

---

## 4. 项目介绍框架（选一套，讲顺）
- **韩式**：**需求 → 数据 → 方案 → 难点 → 结果**。
- 或标准四段：**项目背景 → 个人负责部分 → 项目流程 → 项目成果**。
- 两者等价；关键是用上述"具体化改写"往里填肉，别只剩框架空转。
