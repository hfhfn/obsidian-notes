# 🌐 Nginx · 代理与负载均衡（能说两句）

> [!abstract] 说明
> 面试提到 Nginx 时，主要说的是它**做反向代理、负载均衡、访问控制（限流）**。能说清这几块 + 和高并发的联系即可。

## Nginx 是什么（一句话）
> 一个高性能 **Web 服务器 / 反向代理服务器**，也常做 **负载均衡** 和 **访问控制**。生产里通常是流量入口那一层。

## 三个核心作用（能讲清）
1. **反向代理（reverse proxy）**：隐藏后端真实服务，客户端统一打 Nginx、由它转发到后端；可配合 **静态资源直接返回**，减小后端压力。
2. **负载均衡**：把请求分发给多个后端实例，实现**横向扩展**与高可用。常用策略：
   - **轮询（round-robin）**：依次分发，最简单。
   - **权重（weight）**：按实例能力配权。
   - **IP/会话 hash（ip_hash）**：同一客户端稳定打到同一台（粘性会话，配合 session/缓存）。
   - **least_conn**：发给当前连接数最少的。
3. **访问控制 / 限流**：
   - **`limit_req`**——按速率限流（如每秒 N 次）；**`limit_conn`**——按连接数限流；`allow/deny` 做 IP 黑白名单。
   - 这些正好是「网关层限流」的实现之一（见 [[工作/面试收集/20_专题研究/并发限流-工程化|并发限流-工程化]]）。

## 和你的项目怎么接（面试口径）
- "高并发对外，前面挂 **Nginx 做反向代理 + 负载均衡 + limit_req 限流**，把流量控住再进我的服务，实现横向扩容与非业务攻击的兜底。"
- 一句补位：如果你不负责 Nginx 细节，可以说"**生产是 Nginx 统一入口，负责代理/负载/访问控制，具体配置 SRE 维护，我清楚链路**"——既懂又不越权。

## 一句话记忆
> Nginx = 高性能反向代理 + 负载均衡（轮询/权重/ip_hash/least_conn）+ 访问控制（limit_req/limit_conn）；做流量入口、挡第一层限流，配合后端横向扩容。
