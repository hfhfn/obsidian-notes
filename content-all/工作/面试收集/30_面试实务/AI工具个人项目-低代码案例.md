# 🧰 AI 编码工具个人项目 & 低代码案例（备一两个能讲）

> [!abstract] 说明
> 面试两次被问到：**"有没有用 AI 编码工具自己做过什么小项目？"** 和 **"有没有自己做过 coze 之类的项目？"**——你都卡住。这篇给你**成套剧本**：挑 2~3 个真能顺下来的讲，别编太远。

---

## 1. vibe coding 个人小项目（从"日常真实需求"里挑，最真实）
> 原则：**别挑你不会的**——选你能讲清"输入→处理→输出 / 技术栈 / 主动踩过什么坑"的。语气是"用 AI 帮我做生活/工作里的一个具体小工具"。

**候选池（选 2~3 个，按你真实偏好挑）**
1. **批量文档转 Markdown/抽表格**：一堆 PDF/Word → 用 AI 写脚本统一转 md、按规则分 chunk、抽表格。
   - 能讲：用什么（Claude Code/Python + 解析库）、处理多少份、输出去哪。
2. **个人知识库(Obsidian)自动化**：抓取/剪藏去重、按模板归类、定时整理。← *你在用的场景，最真*。
   - 能讲：Obsidian Web Clipper + agent 维护 wiki（正好扣上 LLM-Wiki）。
3. **一键 Markdown→PPT/海报（Marp）**：把笔记/大纲转成幻灯片或一张海报。
   - 能讲：Marp 插件 + 脚本，配出图。
4. **本地 RAG 问答 bot**：把自己笔记向量化 + 检索，做"问我的笔记"。
   - 能讲：embedding(bge-m3) + Milvus/纯文件 + 检索，和简历 RAG 呼应。
5. **数据清洗/报表脚本**：用 AI 写 pandas 洗 CSV、出图（matplotlib）。
   - 能讲：字段/去重/缺失处理 + 图表。
6. **群/客服小机器人**：接大模型 API 做个查知识、答疑小 bot。
   - 能讲：接 API + 简单状态管理 + 限流/重试。
7. **网页/价格监控**：定时抓页面变化，AI 概括成摘要推送。
   - 能讲：`curl`+`cron`/action + 用 LLM 总结。

**怎么讲不虚**：哪怕很小，也按「需求 → 我用了什么工具和模型 → 关键技术点(输入/处理/输出/踩了什么坑/怎么兜底)」交代清楚；**讲"踩过的一个坑你怎么解决的"比讲功能更可信**。

## 2. 低代码平台（Coze / Dify）案例
> 被问"有没有做过 coze 项目"时，挑一个能讲清"搭了什么流、解决什么问题"的。

**候选池（选 1~2）**
1. **知识问答 / 客服机器人**：上传知识库 + 大模型回复 + 引用来源。→ 强调"RAG 在低代码里的落地，我懂原理所以能讲清节点怎么搭"。
2. **日报/周报自动生成工作流**：接多人数据 → 模板化生成 → 定时推送。→ 强调"触发+模板+变量替换"。
3. **文档问答 / 总结 bot**：把长文档喂进去让它总结/抽要点。
4. **数据查询助手**：接 API/数据库，人能自然语言问数据 → 转查询 → 返回结果。→ 强调"工具调用/结构化输出"（扣 function-call + JSON 四件套）。
5. **群运营机器人**：定时话题、欢迎、问答、素材。

**加分句式**
> "低代码平台我懂的是**背后的原理**（RAG/工作流/工具调用/JSON 约束），所以即使我没在 coze 上堆很多，也能讲清怎么搭、怎么调优——而我们 toB 自建就是用这些同样的思路。"

## 3. 业务向 & 二面深挖（这家偏业务）
- 一面技术点二面会**深挖**：Multi-Agent State、RRF、蒸馏、subagent 权限、知识库多租户权限 → 预先把这几个做成"能讲 60 秒 + 能接追问"。
- **业务准备**：他们的"AI 同步工程师"重业务，很可能让你介绍**之前的业务**（如商家资质审核的业务流转：资质有哪些、审核规则、A/B 不可见、异常怎么兜）→ 把"需求-数据-方案-难点-结果"顺一遍你的业务。
- 准备 1 个"给某个业务环节提一个能落地的 AI 优化方案"的即兴题。

## 4. 60 秒口述剧本（可直接背，挑与你有交集的认领）

> ⚠️ **诚实第一**：以下按你已用的工具栈写的。**没真做过的项目，投前拿 Claude Code 跑一遍**再认领，被追问细节才站得住。

### A. Obsidian 知识库自动化（vibe coding，最稳·你有真实践）
> "我一直在用 Obsidian，日常剪藏、笔记很多。我用 AI 编码工具让 LLM 当'整理我的知识库的程序员'：把新丢进来的文章/剪藏，按统一模板生成摘要、自动归类、补双链，再更新一份 index。"
- **技术要点**：Markdown + `[剪藏→md]` → LLM 抽信息/打标签/写页/更新 index；Obsidian Web Clipper 收源。
- **踩坑**：一开始 LLM 乱建文件/双链乱——后来给它一份 `CLAUDE.md` 约定"目录结构+命名规范+必须更新 index"，就跑偏少了。
- **收尾句**：这就是"LLM-Wiki 模式"在个人层我的实践，也让我更懂怎么用 schema 约束 agent。*(正好接住真题复盘 Q9)*

### A'．Obsidian 知识库自动化（贴身版，推荐主打）
> **就是你现在正在做的事**：你在 Obsidian 里让 AI 助手（我这类 agent）帮你**持续维护一套面试知识库**——按主题归档、优化表述、补齐双链、更新 MOC 索引、给每题配"一句话记忆"。这道题直接讲真实过程，最有说服力。

**60 秒口述（用你当下实况）**
> "我一直在用 Obsidian 管理知识，最近让 AI 编码助手帮我在里面维护一个面试知识库：我隔三差五把复盘/题目丢进主题文件，它帮我优化措辞、补双链、整理成统一结构、刷一遍索引。相当于一个我自己日常在用的 LLM-Wiki——Obsidian 是 IDE，AI 是帮我写和维护知识库的程序员。"
- **技术要点**：Markdown + frontmatter(tags/status) + wikilink + MOC 索引 + Dataview；Web Clipper 收源；版本管理(git)。
- **踩坑**：AI 一开始会建松散、命名不统一的文件、链接维护不到位——我给它一份 `CLAUDE.md` 约定"目录结构 + 命名规范 + 每篇要有模板和双链 + 更新 MOC"，并让它"能复用不新建、留一句话记忆"，跑偏就少了。
- **收尾句**：这既是我的日常工具，也让我真懂 agent 怎么被"约定/模板/索引"约束着干活——不是只用提示词糊一次。*(同时回答 Q20 怎么提升自己 + Q9 LLM-Wiki + Q13/17 你用 AI 工具干嘛)*

### B. 批量 PDF/Excel → 结构化 Markdown（vibe coding，接你 RAG 简历）
> "工作中常收到一堆 PDF/Excel，要转成可用文本、抽表格进知识库。我让 AI 编码工具写解析脚本：文本直接提，图片/表格单独提取并带位置信息，输出成结构化文本。"
- **技术要点**：Claude Code/Cursor + Python(`mupdf`/`pdfplumber`/`pandas`)；文本块/图片块/表格块带 `(type,page,索引)` 元数据。
- **踩坑**：直接全量转文本会把表格和版式打乱、检索定位不准——后来分块提取保留元数据，才能引用到正确位置。
- **收尾句**：这就是我生产 RAG 前置解析的一个 mini 版。*(呼应 05·Q2 多模态解析)*

### C. 本地 RAG 问答（vibe coding，呼应 Milvus+bge-m3）
> "我想'问自己的笔记'，做了个本地检索问答：文档分 chunk + bge-m3 向量化 + 检索 topk + 大模型生成带引用的回答。"
- **技术要点**：Python + `bge-m3` + Milvus/轻量本地检索 + 大模型 API。
- **踩坑**：纯向量召回会漏词法命中关键词——后来加 **dense+sparse 混合 + RRF 融合**，命中明显变好。
- **收尾句**：和简历里'召回 60→78%'是同一套思路的小规模验证。*(直接支撑你在 RRF 那道题上的可信度)*

### D. 客服知识问答 bot（Coze 低代码，讲"原理"而不仅是拖节点）
> "我用 Coze 搭过一个知识问答 bot：传 FAQ/文档建知识库 + 大模型节点生成回复 + 带引用来源。我重点能讲的是背后原理——分块、检索、引用定位，而不只是会拖几个节点。"
- **技术要点**：知识库(分块/embedding) → 检索 → 生成+来源引用；后端是 RAG。*(扣 05·Q2)*

### E. 日报/周报自动生成工作流（Coze/Dify，能接"数据查询"）
> "搭过一个周报工作流：多人/多源内容输入 → 模板变量 → LLM 汇总成结构化周报 → 定时推送。结构化输出和触发是它的关键。"
- **技术要点**：触发(定时/按钮) + 输入收集 + 模板 + 结构化输出(JSON);可外接数据库/API 做成"自然语言查数据"。
