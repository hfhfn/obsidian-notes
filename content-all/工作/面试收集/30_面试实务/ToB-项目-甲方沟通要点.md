# 🤝 ToB / ToG 项目 · 甲方沟通要点

> [!abstract] 说明
> ToB/ToG 项目里，开发或技术负责人免不了**跟甲方（客户）沟通项目落地的细节**，事无巨细、沟通频繁。面试官常借此考察你的项目落地能力和沟通协作，不只写码。结合你投的岗位方向，提前准备怎么"讲过程、讲对齐"。

## 沟通涉及的四大类

| 类别 | 要讲清的细节 |
|------|-------------|
| **数据** | 数据源/格式/脱敏/权限/样例数据谁提供、怎么拿、缺数据怎么办 |
| **实现方案** | 技术选型、对接方式（API/SDK/中间件/文件交换）、改动面、工期 |
| **对接平台** | 对方系统怎么打通：鉴权、协议、字段映射、联调环境、谁做联调 |
| **交付标准** | 验收指标、交付物、文档、培训、维保期、变更怎么控 |

## 面试怎么讲（别只报"我做了 XX"）
- 讲清一个完整闭环：**需求对齐 → 数据/平台前置条件确认 → 方案评审 → 联调 → 验收 → 移交文档/培训**。
- 有货的加分点是**处理和甲方的冲突/变更**：需求变更怎么评估影响、怎么拒绝或分级、怎么书面留痕。
- 一句话立场："我不仅能写代码，还能把项目从对接到交付的项目落地闭环说清楚。"

## 一句话记忆
> ToB 落地 = 数据 + 实现方案 + 平台对接 + 交付标准 **四件事跟甲方对齐**；能把"对齐流程 + 变更处理"讲清楚，就证明你有项目落地与沟通能力。
