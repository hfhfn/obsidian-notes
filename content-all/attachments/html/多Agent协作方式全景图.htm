8.8 多 Agent 智能体 · 七种协作方式全景图

横轴 = 编排重心（静态/硬编码 → 动态/协商）｜ 纵轴 = 开放度（应用内/框架内 → 跨应用/开放）｜ 三个 ★ 为 8.8 重点对比方

第 8 章 vs A2A —— 一个「导演」，一个「外交协议」

🎬 第 8 章 Orchestrator（应用内）

  • 通信：进程内直调 graph.ainvoke
  • 编排：中心调度器 + 硬编码 Pipeline
  • 发现：_LABEL_TO_AGENT 映射表（写死）
  • 开放度：封闭 · 同框架 LangGraph · 单进程
  • 状态：共享 MemorySaver 检查点（thread_id）

→ 高效、可控、省；但只在「这个剧组」内有效。

🤝 A2A 协议（跨应用）

  • 通信：JSON-RPC 2.0 走 HTTP/SSE/WebSocket
  • 编排：去中心 · 任何 Agent 都能给任何 Agent 派任务
  • 发现：动态 Agent Card（Well-Known URL）+ 目录
  • 开放度：开放 · 框架无关 · 跨厂商
  • 状态：任务级状态机（working/completed/…）

→ 开放、标准、可扩展；但不管「内部怎么编排」。

二者互补：对内（同框架同进程）用 Orchestrator，对外（跨系统互操作）用 A2A —— MCP 管 Agent↔Tool，A2A 管 Agent↔Agent。
