## 整体流程

### 1. **两个部署环境**

- **测试环境 (deploy-test)**: 当你推送到 `v1.0.0` 分支时触发
- **生产环境 (deploy-prod)**: 需要手动触发,选择 `sg-prod-deploy` 标签,只在 `main` 分支执行

### 2. **部署流程**

每个环境的部署步骤都是:

1. 移动并替换 deployment.yaml 文件
2. 用 Git commit 的短 SHA 替换配置中的变量
3. 使用 kubectl 应用配置到对应的 K8s 环境

## 作为开发人员你应该这样做

### **日常开发流程**
```
main (主分支)
  ↓
feature/xxx (功能分支) ← 你在这里开发
  ↓
v1.0.0 (测试分支) ← 推送到这里会自动部署测试环境
  ↓
main (合并回主分支) ← 生产环境从这里手动触发部署
```

### **具体操作步骤**

#### **第一步:功能开发**
```bash
# 从 main 分支创建功能分支
git checkout main
git pull origin main
git checkout -b feature/your-feature-name

# 开发并提交
git add .
git commit -m "feat: 你的功能描述"
```

#### **第二步:测试环境部署**
```bash
# 推送到 v1.0.0 分支触发测试环境自动部署
git checkout v1.0.0
git pull origin v1.0.0
git merge feature/your-feature-name
git push origin v1.0.0

# 此时会自动触发 deploy-test,部署到测试环境
```

#### **第三步:测试通过后合并到 main**
```bash
# 测试通过后,合并到 main 分支
git checkout main
git pull origin main
git merge feature/your-feature-name
git push origin main
```

#### **第四步:通知运维部署生产环境**
```bash
# 此时你需要通知运维人员:
# "我已经将功能合并到 main 分支,请帮忙部署生产环境"
```

## 与运维的配合方式

### **你负责:**

1.  在功能分支开发代码
2.  推送到 `v1.0.0` 分支进行测试环境部署
3.  在测试环境验证功能
4.  测试通过后合并到 `main` 分支
5.  通知运维部署生产环境

### **运维负责:**

1.  在 GitLab CI/CD 界面手动触发 `deploy-prod` 任务
2.  选择 `sg-prod-deploy` 标签
3.  监控生产环境部署状态
4.  K8s 集群配置和维护(你不需要修改)

## 关键注意事项

**不要直接推送到 main 分支做测试** - 应该推送到 `v1.0.0`

**生产环境不会自动部署** - 必须通知运维手动触发

**K8s 配置文件(k8s/base/和k8s/overlays/)不要修改** - 运维已经配置好

**你只需要关注应用代码** - 部署配置已经由运维处理好了

## 简化步骤
```
开发 → feature 分支
测试 → 推送到 v1.0.0 (自动部署测试环境)
生产 → 合并到 main → 通知运维 (手动部署生产环境)
```
