## 要点解释:

## 1. `sg-prod-deploy` 标签是什么？

这里的**标签(tag)**不是 Git 标签，而是 **GitLab Runner 的标签**。
```yaml
tags:
  - sg-prod-deploy  # 这是指定哪台服务器来执行部署任务
```

**作用：**

- 运维在不同的服务器上安装了 GitLab Runner
- 每个 Runner 会打上标签，比如 `sg-prod-deploy` 表示"新加坡生产环境部署服务器"
- 这行配置的意思是：**这个部署任务必须在带有 `sg-prod-deploy` 标签的服务器上执行**

**你不需要关心这个！** 这是运维配置的，用来指定部署任务在哪台机器上运行。

## 2. 手动触发是什么意思？

看这两个配置的区别：
```yaml
# 测试环境 - 自动触发
deploy-test:
  stage: deploy
  when: on_success  # 前面的步骤成功后自动执行
  only:
    - v1.0.0  # 只要推送到 v1.0.0 分支就自动运行

# 生产环境 - 手动触发  
deploy-prod:
  stage: deploy
  when: manual  # ⚠️ 需要人工点击才执行
  only:
    - main  # 只在 main 分支显示这个按钮
```

### **手动触发的实际操作：**

当你推送代码到 `main` 分支后，在 GitLab 界面会看到：
```
GitLab CI/CD Pipeline 界面:
┌─────────────────────────────┐
│ Pipeline #12345             │
│ Branch: main                │
├─────────────────────────────┤
│ ✅ build (已完成)            │
│ ✅ test (已完成)             │
│ ▶️ deploy-prod (等待手动触发) │ ← 这里会有个播放按钮
└─────────────────────────────┘
```

**运维需要：**

1. 进入 GitLab 项目页面
2. 点击 CI/CD → Pipelines
3. 找到对应的 pipeline
4. 点击 `deploy-prod` 旁边的 ▶️ 播放按钮
5. 确认执行

## 3. 你作为开发人员需要打标签吗？

**不需要！** 你只需要：
```bash
# 1. 开发完成后合并到 main
git checkout main
git pull origin main
git merge feature/your-feature
git push origin main

# 2. 然后通知运维
# "我已经推送到 main 了，commit SHA 是 abc123，请帮忙部署生产环境"
```

**就这么简单！** 剩下的都是运维的事。

## 4. 怎么才能只在 main 分支执行？
```yaml
only:
  - main  # 这个配置决定的
```

**这个配置的含义：**

| 你的操作                  | 会发生什么                                    |
| ------------------------- | --------------------------------------------- |
| 推送到 `feature/xxx` 分支 | ❌ 不会显示 `deploy-prod` 任务                 |
| 推送到 `v1.0.0` 分支      | ❌ 不会显示 `deploy-prod` 任务                 |
| 推送到 `main` 分支        | ✅ 会显示 `deploy-prod` 任务（但需要手动点击） |

**这是由 `.gitlab-ci.yml` 配置文件决定的**，不取决于运维人员。

但是：

- **配置文件是运维写的**
- **手动触发的按钮是运维点击的**

## 总结

| 问题                          | 答案                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| `sg-prod-deploy` 标签是什么？ | GitLab Runner 服务器标签，指定在哪台机器运行，**你不需要管** |
| 手动触发是什么意思？          | 运维在 GitLab 界面点击 ▶️ 按钮执行部署，**不是自动的**        |
| 你需要打标签吗？              | **不需要**，你只管推送代码到 main                            |
| 怎么保证只在 main 执行？      | `.gitlab-ci.yml` 里的 `only: - main` 配置决定的              |

**你唯一要做的事：推送代码到 main，然后说一声 "请部署生产环境"，就完事了！** 🎉
