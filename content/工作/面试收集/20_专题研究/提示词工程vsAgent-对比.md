# 提示词工程 vs Agent 系统：系统性对比

> 面试口径一句话：**两者不是对立，而是不同抽象层级的工程手段。提示词是给单次 LLM 调用的"静态激励"，Agent 是围绕多次 LLM 调用的"多步控制流"。Agent 内部每一环仍然在用提示词——提示词是 Agent 的积木/零件，Agent 是提示词的应用形态。**

---

## 一、提示词工程（Prompt Engineering）是什么

### 定义
通过**设计输入给模型的指令文本**，来引导 LLM 在**单次调用**中给出期望输出。它只作用于"模型 + 一次性文本上下文"，不改变模型权重，不动外部世界。

### 涵盖的主要手段
| 手段 | 说明 |
|---|---|
| **指令 / 角色** | 明确任务目标、格式要求；用系统提示设定角色、风格、边界（如"你是一名资深算法工程师"）|
| **Few-shot（少样本示范）** | 在上下文中给几个输入-输出对的例子，让模型模仿格式与推理方式 |
| **CoT 思维链（Chain-of-Thought）** | 引导模型展示中间推理步骤（`Let's think step by step`），提升复杂推理准确率；进阶有 Self-Consistency、CoT-SC 等 |
| **结构化输出** | 要求 JSON / 固定字段 / 用工具定义 schema 强制格式（如 function-calling 的参数 schema）|
| **模板 / 变量的系统化** | 把指令拆成可复用模板（系统提示 + 用户变量），保证一致性与可维护 |
| **提示词管理 / 版本化** | 版本管理、AB 测试、评估集（eval set）回归，防"改一处坏一片" |

### 能达到什么
- 在不调权重的前提下**明显提升单次输出的质量、格式稳定性、领域能力**（靠检索/in-context 示例增强）。
- 成本低、见效快、易迭代，是绝大多数应用的"第一层优化"。
- Anthropic 原文明确建议：**"For many applications, optimizing single LLM calls with retrieval and in-context examples is usually enough."**（多数应用，优化单次调用就够。）

### 局限（关键：答"为什么还要 Agent"）
1. **静态、一次有效**：提示词是*一次性文本激励*，语境固定，不能随过程调整。
2. **无状态**：默认不带记忆/跨步骤持久状态（除上下文窗口内的文本）。
3. **无外部行动**：只输出文本，不能调 API、读写文件、操作工具/世界。
4. **无自我纠正**：单次生成错了就是错了，无法自己发现、重试、兜底。

## 二、Agent 系统是什么

### 定义（Anthropic 权威口径）
> **Agent = 让 LLM 动态地自主决定自己的流程与工具使用**，去达成一个任务。与之相对的 **Workflow（工作流）= 由预定义代码路径编排 LLM 与工具**。

Agent 的本质结构（业界通行）：```
LLM（核心推理）
  + 规划 Planning（拆解目标、决定下一步）
  + 工具 Tool use（调用外部工具 / API）
  + 记忆 Memory（短期上下文 + 长期持久记忆）
  + 环境交互 / 反馈循环（看结果 → 决定下一步 → 循环直到完成）
  + 控制流（多步 + 循环 + 分支，潜在地由代码/编排层兜底）
```

### 关键组成部分
- **基础积木 = 增强型 LLM（Augmented LLM）**：给 LLM 加上 **Retrieval（检索）+ Tools（工具）+ Memory（记忆）**。Anthropic 原文："The basic building block of agentic systems is the augmented LLM... such as retrieval, tools, and memory."
- **工具接入**：现在主流是 **MCP（Model Context Protocol）**，一个统一客户端实现即可接入第三方工具生态。
- **编排层**：决定"谁在控制"——代码预设（Workflow）还是模型自主（Agent）。

### 能力层级（由低级到高级的教学框架）
1. **单次 LLM 调用（提示词）** → 静态问答/生成。
2. **增强型 LLM**（检索+工具+记忆的单次能力增强）。
3. **Workflow**（提示链接 / 路由 / 并行化 / 编排者可 / 评价者-优化者）——行为可预期，代码控制。
4. **Agent**（自主规划 + 工具 + 反馈循环）。
5. **多 Agent（Multi-Agent）**：多个角色各司其职、协作/分工/评审。

## 三、系统性对比（面试重点，能背能展开）

| 维度 | 提示词工程 | Agent 系统 |
|---|---|---|
| **本质** | 静态文本激励（对单次调用的一次性引导） | 多步控制流（对多次调用 + 工具 + 状态的编排）|
| **状态 / 记忆** | 无记忆 / 单次有效 | 有记忆、可持久状态（上下文 + 长期记忆）|
| **行动能力** | 只输出文本 | 可调用工具 / API，作用于外部世界 |
| **是否循环** | 否（一次性） | 是（反馈循环，直至完成或终止）|
| **自我纠正** | 无 | 可基于环境反馈重试/调整路径（仍需编排兜底）|
| **复杂度** | 低，简单可预测 | 高，行为可能发散，需编排、容错与兜底 |
| **确定性** | 高（同一输入输出相对稳定）| 低（多步自主决策，路径不确定，需 guardrail）|
| **成本 / 时间** | 低；单次 token | 高；多次调用 × 多轮循环，延迟与成本均上升 |
| **可维护性** | 模板 + eval + 版本管理相对容易 | 需工具文档、调度、日志、可观测、回滚策略；抽象层多难调试 |
| **失败模式** | 输出偏离格式 / 幻觉 / 答非所问 | 死循环、越权调用、级联错误、工具误用、成本失控 |
| **适用场景** | 明确、单步、格式化任务（分类、抽取、改写、问答）| 需要工具/外部世界、多步骤、不确定性决策、长任务 |

### 协同关系（必答点）
- **Agent 内部全是提示词**：每个节点都是一次"prompt + LLM 调用"。规划器、执行、生成、评审——每一环都在做提示词工程。
- **提示词是 Agent 的"积木/零件"**：基础积木就是"增强型 LLM"= 检索 + 工具 + 记忆，而工具的调用仍依赖提示与 schema。
- even **读 Anthropic 原文**：它的《附录2：Prompt engineering your tools》专门讲"工具定义要像给 Junior 写优秀 docstring 一样，要写示例用法、边界、输入格式"。**工具即提示词的一种形态。**

### 演进路线（能力↑ ⇒ 复杂度/成本↑）```
提示词工程 → Function Calling(工具调用) → Agent → 多 Agent
（静态文本）   （单次可行动）          （多步自主）    （群体协作）
```
- 关键判断：**先"简单回调"再上"复杂 Agent"**。Anthropic 最佳实践明确："Start with the simplest solution possible, and only increase complexity when needed."
- 取舍：agentic 系统**用延迟和成本换更好地完成任务表现**。能用单次调用 + 检索搞定，就别上 Agent。

## 四、面试分层答法（"低→高"口径，能接追问）

1. **先立关系**："两者不是 rival 关系，是不同抽象层级。提示词是单次调用的'微观工程'，Agent 是多次调用的'宏观编排'。"
2. **提示词讲"稳"**：静态、无状态、低成本、确定性高；靠指令/CoT/结构化/示例提升单次质量。
3. **Agent 讲"活"**：有状态、能行动、能循环、能纠错，代价是复杂度/成本/不确定性。
4. **讲桥**：base building block 就是"增强型 LLM（检索+工具+记忆）"；工具（尤其 MCP）与提示词 schema 是承上启下的衔接点。
5. **讲选型**：任务明确→提示词即可；需要外部世界/多步/不确定性→上 Agent；能用简单就别复杂（先简单后复杂）。
6. **收口追问**：
   - "Agent 内部用不用提示词？" → 用，每个节点都是 prompt + 调用。
   - "提示词和 function calling 关系？" → function calling 是"让模型声明要调什么工具"的能力，其参数 schema 本身就是要精心设计的提示。
   - "什么时候 Agent 是过度设计？" → 单步、可枚举、确定性任务；成本/延迟敏感。

## 附：已核实 vs 存疑

- **已核实（Anthropic《Building effective agents》2024-12-19）**：Workflow vs Agent 定义；基础积木=增强型 LLM（检索/工具/记忆）；MCP 是工具接入方式；"优化单次调用通常就够"/"先做最简单的方案"；"Agentic 系统以延迟和成本换性能"；五类 workflow（提示链接/路由/并行化/编排者可/评价者-优化者）；附录2"为工具做提示词工程"。
- **存疑 / 未严格核实（业界通行但非单一权威出处）**：CoT 具体收益数值、工具示例；"提示词→function-calling→Agent→多 Agent"这条演进名词链与"每个节点都是 prompt+调用"这类概括性表述，属通识框架，建议面试以讲逻辑为主，不引用具体数字。
