# 🏗️ 平台化分工协作：底座与业务分层

> [!abstract] 说明
> 面试被追问「你和一个同事分工干 Agent，怎么划分？你交付给他什么？他怎么做？」的**标准打法**。结论：不是流水线、也不是各干各的，而是**平台化分层分工**——你建「可插拔能力底座」，同事当「业务方」在自己业务子图上盖房子。**底部附一套相对完整的 Pydantic v2 代码 demo。**

---

## 1. 先答「你们是哪种分工」

面试官通常先抛一个二选一：
- **垂直分工（端到端）**：你我各做一个完整的 Agent，互不交叉。
- **流水线/横切分工**：一条工作流 1234，你做 1-2，他做 3-4，中间对接。

> [!warning] 关键区分
> 你们实际是**「平台型分工」**（第三种，面试官想听的就是这个）——**你建平台，他在平台上盖房子**。既不是纯流水线，也不是各干各的。要先把这个定性说清楚，别含糊。

**一句话定性**
> "我们用的是**平台化分层分工**：我负责与业务无关的『底座能力』，同事在我提供的 SDK/扩展接口上实现各自的业务节点，通过注册机制挂载，两边靠接口契约松耦合协作。"

---

## 2. 分工边界（谁能说清谁的）

| 层 | 谁负责 | 包含什么 | 是否带业务 |
|----|--------|----------|-----------|
| **业务应用层** | 同事 | 资质审核 Agent / 电商客服 Agent / 其他业务 Agent | ❌ 全部是业务 |
| **业务扩展层** | 同事 | 业务节点、业务 Prompt、业务 Pydantic Schema、业务降级策略 | ✅ 只放业务 |
| **底座能力层** | 你 | LangGraph 主流程编排、全局 State、意图路由、公共工具(RAG/LLM/OCR/PDF)、Checkpointer、日志链路、分级降级熔断 | ❌ **不掺业务** |
| **基础设施层** | 共管 | Redis / PG / 向量库 / 对象存储 | — |

> [!tip] 底座的铁律
> **底座不写死业务**：不允许在底座代码里出现「资质审核」「客服」这类业务逻辑/提示词/校验。底座只做通用基础能力，并**留好子图扩展入口**。这是「底座做厚、业务做薄」的落点。

---

## 3. 交付物（别再说「一套平台的功底和能力」——不可验收）

面试官最会抓的就是「你交付了什么给他」。标准答案：

| 交付物 | 形式 | 验收标准 |
|--------|------|----------|
| 接口文档 | OpenAPI / Markdown | 每个扩展点有定义和示例 |
| 平台 SDK | Python 包（`pip install platform-sdk`） | 同事 `from platform import *` 即可用 |
| 本地开发环境 | Docker Compose 一键起 | 同事本地能跑通全链路 |
| 单元测试 | pytest | 底座接口覆盖 >80% |
| 示例业务 | 一个「Hello World」Agent | 同事照着改就能出自己 Agent |
| 联调工具 | CLI / Web 调试面板 | 同事能独立调试自己的业务节点 |

**一句话记忆**
> "我交付的是**SDK + 接口文档 + 本地环境 + 示例代码**，不是原始数据、也不是半成品代码。他 `pip install` 引入底座，注册自己的节点后独立部署上线。"

---

## 4. 协作 SOP（需求/开发/变更三阶段）

**需求阶段**（一次性对齐）
1. 一起梳理两个 Agent 需要的**全部能力清单**。
2. 归类：哪些公用（底座做）、哪些业务（业务方做）。
3. 定接口：底座向业务暴露哪些**扩展点**。
4. 排期：底座先做基建，业务方同时写业务逻辑（**不互相阻塞**）。

**开发阶段**（持续）
- 底座侧：实现通用能力 → 预留扩展点 → 写单测 → 给示例。
- 业务侧：基于 SDK 开发 → 本地 Mock 验证 → 与底座联调。

**变更流程**（面试加分，体现工程化）
- 同事需要新能力 → 提需求单（要什么/为什么/期望时间）→ 底座评估排期 → 升 SDK 版本 → 无感接入。
- 底座要改影响业务 → **必须向后兼容**；破坏性变更提前通知 + 迁移指南 + Deprecation Warning 缓冲期。

---

## 5. 💻 相对完整的代码 demo（Pydantic v2）

> 一套「底座 + 业务方」能在本地跑通的骨架。**全程用 Pydantic v2 语法**（`BaseModel`/`Field`/`field_validator`/`model_validator`/`model_dump`/`model_validate`，不用 v1 的 `.dict()`/`parse_obj()`/`validators`）。

### 5.1 底座侧：定义扩展点 + 全局 State（你负责）
```python
# ============ 底座：platform/core.py（你负责，不含业务） ============
from __future__ import annotations

import logging
from abc import ABC, abstractmethod
from typing import Any, Protocol, runtime_checkable

from pydantic import BaseModel, ConfigDict


# ---------- 1. 全局 State（底座定义，业务方只读写约定字段） ----------
class AgentState(BaseModel):
    model_config = ConfigDict(extra="forbid")  # Pydantic v2：禁止未知字段，提早暴露拼写错误

    # 会话/任务层
    session_id: str
    task_id: str
    intent: str = ""
    current_agent: str = ""

    # 业务数据（由业务子图写入）
    extracted: dict[str, Any] = {}          # 结构化抽取结果
    review_status: str = ""                  # pending / pass / reject / manual
    confidence: float = 0.0                  # 置信度，用于降级决策
    error_log: list[str] = []                # 节点失败记录

    # Pydantic v2 CRUD
    # model_config / Field 均可；序列化用 model_dump()
    def snapshot(self) -> dict[str, Any]:
        return self.model_dump()

    @classmethod
    def restore(cls, data: dict[str, Any]) -> "AgentState":
        return cls.model_validate(data)      # v2 的校验入口（v1 是 parse_obj）


# ---------- 2. 业务节点扩展点（业务方必须实现） ----------
@runtime_checkable
class BusinessNode(Protocol):
    """业务节点接口：业务方实现具体逻辑"""
    def execute(self, state: dict[str, Any]) -> dict[str, Any]:
        """入参是 state 快照(dict)，返回要 merge 回 state 的字段(dict)"""
        ...


# ---------- 3. 公共能力（底座提供，业务方复用） ----------
class BaseLLM:
    def call(self, prompt: str, *, schema: type[BaseModel] | None = None) -> Any:
        """统一 LLM 调用：重试 / 限流 / 结构化输出(传 schema 走 Pydantic 校验)"""
        raw = self._invoke(prompt)               # 假实现，真实接 API
        if schema is not None:
            return schema.model_validate(raw)    # v2：校验失败抛 ValidationError
        return raw

    def _invoke(self, prompt: str) -> Any:
        raise NotImplementedError("接入你的大模型 API")


class BaseOCR:
    def extract(self, file_url: str) -> str:
        raise NotImplementedError("接入 OCR 服务")


# ---------- 4. 底座装配器：注册业务节点，拼装业务子图 ----------
class AgentPlatform:
    def __init__(self, logger: logging.Logger | None = None) -> None:
        self._nodes: dict[str, BusinessNode] = {}
        self.llm = BaseLLM()
        self.ocr = BaseOCR()
        self.logger = logger or logging.getLogger("platform")

    def register_node(self, node_name: str, node: BusinessNode) -> "AgentPlatform":
        """业务方注册自己的节点"""
        self._nodes[node_name] = node
        self.logger.info("register_node: %s", node_name)
        return self

    def run(self, state: AgentState) -> AgentState:
        """按注册顺序执行业务节点，每步打日志 + 落 checkpoint（演示）"""
        for name, node in self._nodes.items():
            self.logger.info("[%s] IN  %s", name, state.snapshot())
            patch = node.execute(state.snapshot())   # 业务方节点消费 dict
            state = state.model_copy(update=patch)   # v2：按字段更新并重建
            self.logger.info("[%s] OUT %s", name, state.snapshot())
            # TODO: 在这里把 state.snapshot() 交给 LangGraph Checkpointer 持久化
        return state
```

### 5.2 业务方：定义 Pydantic v2 Schema + 实现业务节点
```python
# ============ 业务方：merchant_audit/schema.py（同事负责） ============
from typing import Literal

from pydantic import BaseModel, Field, field_validator, model_validator


# ---------- 业务专属 Schema：营业执照信息抽取结果 ----------
class LicenseInfo(BaseModel):
    company_name: str
    unified_code: str = Field(..., min_length=18, max_length=18,
                              description="统一社会信用代码：18位")
    legal_person: str
    business_scope: str

    # Pydantic v2 : field_validator（v1 是 @validator）
    @field_validator("unified_code")
    @classmethod
    def _code_alnum(cls, v: str) -> str:
        if not v.isalnum():
            raise ValueError(f"统一信用代码必须为字母数字：{v}")
        return v.upper()

    # 全局约束校验
    @model_validator(mode="after")   # v2 推荐写法
    def _company_name_legal(self) -> "LicenseInfo":
        # 审核业务规则：公司名应含企业性质后缀（示例规则）
        if not any(k in self.company_name for k in ("有限公司", "股份有限公司", "公司")):
            self.confidence_penalty = True   # 仅示意
        return self


class AuditResult(BaseModel):
    status: Literal["pass", "reject", "manual"]   # manual → 走降级人工
    license: LicenseInfo | None = None
    confidence: float = Field(default=0.0, ge=0.0, le=1.0)
    reasons: list[str] = []


# ============ 业务方：节点实现（同事负责） ============
# 商家资质审核的「内部节点」链：抽取 → 校验 → 判活/降级


class ExtractLicenseNode:
    """OCR + LLM → 结构化字段（走 Pydantic v2 校验）"""
    def execute(self, state: dict[str, Any]) -> dict[str, Any]:
        ocr_text = state["_ocr_text"]
        llm = state["_llm"]                        # 底座注入
        license = llm.call(
            f"从以下原文抽取营业执照字段：\n{ocr_text}",
            schema=LicenseInfo,                    # 强制结构化 + 校验
        )
        return {"license_model": license.model_dump()}   # v2: model_dump()


class ValidateLicenseNode:
    """校验 + 如需人工 → 置 status=manual（即降级）"""
    def execute(self, state: dict[str, Any]) -> dict[str, Any]:
        lic = LicenseInfo.model_validate(state["license_model"])  # v2 校验入口
        # ...业务校验规则...
        ok = all([lic.company_name, lic.unified_code, lic.legal_person])
        return {
            "review_status": "pass" if ok else "manual",
            "confidence": 0.95 if ok else 0.3,
            "extracted": lic.model_dump(),
        }
```

### 5.3 装配：把业务节点挂到底座上（两边解耦的落点）
```python
# ============ 组装 main.py ============
import logging
logging.basicConfig(level=logging.INFO)

from platform.core import AgentPlatform, AgentState    # 「你」交付的 SDK
from merchant_audit.nodes import ExtractLicenseNode, ValidateLicenseNode

# 同事：用自己的业务节点装配，不碰底座源码
platform = (
    AgentPlatform()
    .register_node("extract_license", ExtractLicenseNode())
    .register_node("validate_license", ValidateLicenseNode())
)

st = AgentState(session_id="s1", task_id="t_001", intent="audit")
st = platform.run(st)
print("最终状态:", st.snapshot())
print("审核结论 :", st.review_status, "置信度:", st.confidence)
```

### 5.4 demo 里的 Pydantic v2 知识点（面试可点）

| v1（旧） | v2（本项目用） | 说明 |
|---------|---------------|------|
| `@validator` | `@field_validator` | 单字段校验；`@classmethod` |
| `@root_validator(pre=True)` | `@model_validator(mode="before"/"after")` | 整模型/多字段约束 |
| `.dict()` | `.model_dump()` | 序列化为 dict |
| `Model.parse_obj(x)` | `Model.model_validate(x)` | 构建+校验 |
| `Model(**x)` 即校验 | 直接 `Model(...)` 也校验 | 构造即触发 validator |
| `class Config: ...` | `model_config = ConfigDict(...)` | 类级配置（extra/from_attributes） |
| `Optional[X]`/`Field(default=...)` | `X | None` / `Field(...)` | 可选字段写法更简洁 |

> [!note] 要给面试官的一句话
> "我们的结构化输出和状态校验**统一用 Pydantic v2 的 `field_validator`+`model_validator`+`model_dump`**，LLM 抽取结果强制走 `model_validate`，校验失败即节点报错可回退，多项失败直接触发**业务降级**转人工。"
