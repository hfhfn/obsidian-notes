## 1. 工具路由层如何同时保证高召回和高准确率？

| | 答案 |
|---|---|
| 📖 **面经答案** | 用向量检索召回，再用规则过滤。 |
| ⚙️ **实战答案** | **三层漏斗设计** |

**三层漏斗详解：**

- **第一层 — 规则过滤**：过滤掉明显不匹配的工具（如权限、环境），召回率 90%
- **第二层 — 向量检索**：召回 Top 15，保证覆盖
- **第三层 — 精调小模型**：对工具参数做预匹配，筛掉参数不兼容的工具，最终输出 Top 3

**实战数据（电商客服系统）：**
- 误召回率：25% → **3%**
- 漏召回增加：仅 **1.2%**

## 2. 工具描述与实际功能出现偏差时，如何让系统自适应？

| | 答案 |
|---|---|
| 📖 **面经答案** | 定期更新工具描述，确保准确。 |
| ⚙️ **实战答案** | **建立工具健康度反馈闭环** |

**闭环机制：**

1. 每次调用后收集：成功率、耗时、结果质量
2. 自动为工具打上**置信度标签**
3. 当工具连续出现「模型选中但执行失败」时，自动触发**描述优化流程**
4. 用真实调用记录生成更精准的描述

**实战案例：** 「物流查询」工具因描述模糊被滥用，通过闭环优化，调用准确率提升 **40%**。

## 3. 长对话中，如何防止早期片段污染后续决策？

| | 答案 |
|---|---|
| 📖 **面经答案** | 用向量检索按需召回，避免全量注入。 |
| ⚙️ **实战答案** | **时间衰减的注意力机制** |

**设计要点：**

- 为每段对话标记**时间**和**重要性权重**
- 新对话默认权重 1.0，旧对话按**指数衰减**
- 识别对话阶段转折点（如用户说「换个话题」），自动降低之前片段权重

**实战数据（客服系统）：**
- 跨阶段误解率降低：**60%**
- 关键信息遗忘率增加：仅 **2%**

## 4. 并行调用时，如何设计优先级和资源分配策略？

| | 答案 |
|---|---|
| 📖 **面经答案** | 按依赖关系确定执行顺序，无依赖的并行执行。 |
| ⚙️ **实战答案** | **多维度调度队列 + 全局预算池** |

**队列分级（三维评分：耗时、成本、重要性）：**

| 队列类型 | 适用工具 |
|---|---|
| 实时队列 | 秒级完成的工具 |
| 低优先级队列 | 高成本工具 |
| 插队通道 | 关键路径工具 |

**全局预算池：** 防止单次对话消耗过多资源。

**实战数据：** 引入预算池后，API 成本降低 **35%**，超时率仅上升 **1.5%**。

## 5. 用户说「和上次一样」，历史有 10 次类似操作，如何确定指代？

| | 答案 |
|---|---|
| 📖 **面经答案** | 找时间最近、操作最相似的一次。 |
| ⚙️ **实战答案** | **多模态指代消解（四信号综合打分）** |

**四个信号：**

1. 当前上下文语义相关性（embedding 相似度）
2. 操作结果满意度（用户是否点赞/复购）
3. 时间衰减系数
4. 会话转移模式（用户是否经常在该场景下指代特定操作）

综合打分后，给出 **1~3 个带置信度的选项**让用户确认。

**实战数据：** 准确率 **92%**，询问次数减少 **70%**。

## 6. 如何为 Agent 系统设计「熔断降级」策略？

| | 答案 |
|---|---|
| 📖 **面经答案** | 监控错误率，超过阈值就熔断。 |
| ⚙️ **实战答案** | **分级熔断与优雅降级（三级体系）** |

**三级熔断：**

| 级别 | 触发条件 | 降级策略 |
|---|---|---|
| 工具级 | 单工具失败率 > 10% | 暂停使用，保留基础功能 |
| 模块级 | RAG 系统异常 | 自动切换到规则问答模式 |
| 系统级 | 整体性能下降 | 逐步关闭高级功能，保证核心流程可用 |

**实战数据（618 大促）：** 系统可用性：**99.5% → 99.95%**

## 7. 如何用 3 个核心指标快速判断 Agent 系统健康状况？

| | 答案 |
|---|---|
| 📖 **面经答案** | 成功率、耗时、用户满意度。 |
| ⚙️ **实战答案** | **黄金三角指标** |

**三角指标详解：**

| 指标 | 定义 | 反映问题 |
|---|---|---|
| **任务衰减率** | 任务每轮对话的完成进度增量 | Agent 是否在有效推进 |
| **工具过筛率** | 模型选中但被系统否决的工具比例 | 工具描述与实际的匹配度 |
| **上下文污染指数** | 无关历史被召回的次数 | 记忆系统的有效性 |

> 这三个指标能在 **5 分钟内定位 80% 的问题**。

## 8. 如何设计一个可解释的评估体系，而不仅仅是数字？

| | 答案 |
|---|---|
| 📖 **面经答案** | A/B 测试，看哪个版本效果更好。 |
| ⚙️ **实战答案** | **可归因的评估链路** |

**评估结果必须能追溯三个维度：**

1. **哪个模块**导致差异（规划 / 工具 / 记忆）
2. **具体什么行为**（过度询问 / 幻觉 / 工具误选）
3. **什么场景下**发生（新用户 / 老用户、简单 / 复杂任务）

**实战数据：** 构建评估溯源看板后，迭代周期：**2 周 → 3 天**

## 9. 如何一句话讲清 CoT、ToT、Graph of Thoughts 的本质差异？

| | 答案 |
|---|---|
| 📖 **面经答案** | 分别是链式思考、树状思考、图状思考。 |
| ⚙️ **实战答案** | **三种不同的「思考空间探索策略」** |

**本质对比：**

| 方法 | 探索策略 | 适用场景 |
|---|---|---|
| **CoT** | 深度优先的单路径探索 | 问题路径清晰、状态线性 |
| **ToT** | 宽度优先的多路径试探 | 问题空间可枚举、评估成本低 |
| **Graph of Thoughts** | 带条件跳转的状态机遍历 | 有明确状态转移规则的复杂问题 |

**选择依据：** 问题空间是否可枚举、评估成本高低、是否有明确的状态转移规则。

## 10. 如果让你重写 LangChain，第一个要砍掉的功能是什么？

| | 答案 |
|---|---|
| 📖 **面经答案** | 文档加载器，因为太臃肿。 |
| ⚙️ **实战答案** | **全局状态管理器** |

**理由：**

- 隐式的全局状态是分布式系统的噩梦
- 强制所有状态**显式传递**，每个操作都是**纯函数**
- 虽然初期开发更繁琐，但使调试、测试、扩展成本**降低一个数量级**

**实战数据：** 坚持这个原则的内部框架，线上问题定位时间平均缩短 **80%**。
