# 📈 AI 数据价值重估：Trace · Eval · Governance

> [!abstract] 一句话总结
> 模型不再缺答案时，真正稀缺的不是更多内容，而是**组织怎样把事情做成**的可学习过程。企业 AI 的护城河从「数据堆积」转向「学习速度」：用 **轨迹 Trace** 把真实工作带进系统，用 **评测 Eval** 决定该学什么，用 **治理 Governance** 保证学得安全、可退出。

## 一、结论先行：什么数据还值钱

| 旧判断 | 新判断 |
|---|---|
| 数据价值 = 你有什么内容 | 数据价值 = 你的组织怎样把事情做成 |
| 模型缺常识 | 模型不缺常识，**缺业务边界** |
| 有结果就够了 | **过程**才解释原因：意图、动作、异常、修正 |
| 真实轨迹 = 自动奖励 | 真实不等于正确，还需要黄金任务、评分标准与人审 |
| 预算止于交付 | 稳定预算发生在上线**之后**：评测、失败分析、权限治理、回归测试 |
| 护城河 = 数据堆积 | 护城河 = **发现失败、解释失败、修正系统、安全发布**的速度 |

> [!warning] 一个刺眼的数据
> Gartner 对 1,203 名数据管理负责人的调查显示：**63% 的组织没有、或不确定自己是否具备适用于 AI 的数据管理实践**。AI-ready data 不是一次性项目。

## 二、数据集思维的天花板

传统知识库解决的是「去哪里找到答案」。当 Agent 开始替人行动，问题变成「此刻应该做什么、做到哪一步、什么时候停下来交给人」。

| 传统数据项目 | Agent 运行项目 |
|---|---|
| 收集文档 → 清洗 → 标注 → 交付 | 接到任务 → 使用工具 → 遇到异常 → 修正 → 交付 |
| 最擅长：提供背景知识、统一术语口径、支持检索问答 | 必须理解：目标与优先级、权限与风险边界、例外/升级/停手机制 |
| 盲点：文档记录「组织说过什么」，很少记录「组织为什么这样决定」 | 关键：让系统学习「在约束下完成任务」，而不是生成看起来合理的文字 |

> [!tip] 实用判断
> 如果数据只能回答「正确答案是什么」，它更像**知识**；如果还能回答「为什么这样做、哪里出错、谁修正、结果怎样」，它才开始成为**可学习的业务过程**。

## 三、可学习的工作过程：TRACE 六层

一条真正有用的工作轨迹，不是屏幕录像或聊天记录，而是把一次任务拆成**可解释、可授权、可评测**的结构。

| 层 | 记录什么 |
|---|---|
| ① 任务意图 | 为什么做、要解决什么、成功长什么样 |
| ② 上下文与约束 | 规则、权限、时限、预算、禁区与依赖 |
| ③ 动作与工具 | 查了什么、调用了谁、采取了哪些步骤 |
| ④ 异常与歧义 | 信息缺失、冲突、失败、意外和不确定性 |
| ⑤ 人类修正 | 哪里被改、为什么改、谁有最终决定权 |
| ⑥ 结果与证据 | 交付是否被采用、质量如何、证据在哪里 |

> [!example] 供应商筛选
> 低价值记录只有「已完成筛选」；高价值轨迹还包括候选来源、淘汰理由、风险项、缺失证据、谁做了升级判断，以及最终决策是否经得住复核。

## 四、真实 ≠ 正确：需要一层「评测翻译」

真实业务数据解决的是**分布问题**：让我们看到事情在现实中怎样发生。但它不会自动解决因果归因，也不会自动告诉模型哪一步值得学习。

| 陷阱 | 说明 |
|---|---|
| **外部变量** | 销量受价格、季节、渠道和竞争影响，不能都归因给 Agent |
| **幸存者偏差** | 只保存成功案例，会把运气和不规范操作一起学进去 |
| **延迟反馈** | 关键动作今天发生，真实后果可能数周后才出现 |
| **隐性知识** | 专家凭经验停手或升级，但日志里可能只留下一个点击 |

把真实轨迹变成可学习信号，需要一层「评测翻译」：

```
真实任务 → 黄金样本 → 评分标准 → 人工复核 → 业务指标
          保留上下文    覆盖关键边界    处理灰区    验证价值
```

> **轨迹负责把现实带进系统；评测负责决定系统应该从现实中学什么。**

## 五、生产学习闭环：真正付费的是上线后的改进

一次数据迁移、一次 Prompt 调优、一次演示环境，都可能结束。只要 Agent 真的进入生产，新的失败、规则和权限就会持续出现。

```
运行 → 观察 → 复核 → 更新 → 发布
真实任务进入  记录动作与异常  人类解释失败  评测与流程版本  门禁与监控
```

| 容易一次性结束的预算 | 会随运行持续发生的预算 |
|---|---|
| 数据迁移与初始清洗 | 评测集与规则维护 |
| 首版知识库和 Prompt | 失败分析和人工复核 |
| 演示用任务环境 | 权限、审计与合规门禁 |
| 一次性的模型微调 | 换模型、换工具后的回归测试 |

> [!note] 商业含义
> 比起按条数、人头或标注小时收费，更值得设计的是「**首期诊断与实施 + 持续评测运营 + 可选结果变量费用**」。价值不在「再做一批数据」，而在「让系统持续可靠」。

## 六、模型厂商与企业数据：别把政策当治理

「企业越用模型，经验就越自动变成厂商训练数据」并不准确。至少在当前公开政策下，主流商业产品对客户数据有明确边界：

| 厂商 | 公开政策要点 |
|---|---|
| **OpenAI 商业产品与 API** | ChatGPT Business / Enterprise / Edu 及 API 的输入输出，默认不用于训练；明确选择加入时除外 |
| **Anthropic 商业产品** | 不使用商业客户的聊天或编码会话训练模型，除非客户加入相关计划、明确反馈或主动选择 |

但**公开产品政策不替代合同审查、权限设计和具体法域的合规判断**。企业真正要自己守住五件事：

1. **权限** —— 谁能看、谁能调用、谁能批准高风险动作
2. **保留** —— 数据保留多久、日志能否删除、是否需要本地化
3. **连接器** —— 第三方工具、插件和外部系统会把什么数据带出去
4. **资产化** —— Prompt、Skill、流程和评测是否沉淀在企业可控的系统里
5. **退出** —— 换模型或换供应商时，能力能否迁移、历史记录能否带走

## 七、企业应该沉淀什么：五类复利资产

> 可持续 AI 能力 = **业务语义 × 可验证轨迹 × 迭代速度 × 权利边界**

| # | 资产 | 内容 |
|---|---|---|
| ① | **业务对象模型** | 客户、合同、任务、风险、审批和结果之间的关系 |
| ② | **黄金任务与评测集** | 真正代表业务边界、可反复回归测试的样本 |
| ③ | **错误分类与人工修正** | 失败为什么发生、专家怎样纠正、下一版如何避免 |
| ④ | **运行版本账本** | 模型、Prompt、Skill、Workflow、工具和评测的版本关系 |
| ⑤ | **权利矩阵与审计记录** | 什么可训练、可评测、可保存、可跨域使用，谁批准 |

> [!important] 跨客户复用的边界
> 真正适合复用的是**对象模型、评测方法、错误分类、流程模板和安全门禁**；客户原始内容默认留在客户域内。

## 八、90 天落地：先跑通一个闭环

选择一个**高频、可量化、可人工复核**的窄流程。目标不是做出「万能 Agent」，而是证明失败可以被发现、解释、修正和复测。

| 阶段 | 动作 |
|---|---|
| 第 1–2 周 · 选流程 | 明确负责人、成功标准、禁区与当前基线 |
| 第 3–4 周 · 建结构 | 拆任务对象、权限、数据来源和升级路径 |
| 第 5–8 周 · 采轨迹 | 记录动作与异常，建立首批黄金任务和人审标准 |
| 第 9–12 周 · 影子运行 | 回归测试、发布门禁、小流量试点和业务复盘 |

> [!success] 90 天验收
> 系统能解释主要失败类型；每次改动都有版本；发布前能回归测试；高风险动作有人工批准和回滚。

## 九、怎么判断真的变好了：衡量系统，不是 Demo

Agent 的表现是模型、工具、权限、流程和人的共同结果。只看「准确率」会误判。

| 质量 | 效率 | 业务 | 控制 |
|---|---|---|---|
| 任务成功率 | 人审分钟数 | 周期缩短 | 越权次数 |
| 关键事实错误率 | 单任务综合成本 | 返工减少 | 审计完整性 |
| 严重风险漏检率 | 平均处理时长 | 采用率与完成率 | 回滚与恢复时间 |

## 十、八个判断问题

判断一个 AI 数据机会，先问：

1. 谁拥有数据？谁明确授权了训练、评测、保存和复用？
2. 数据会持续产生，还是交付一次就开始过期？
3. 结果能否被独立验证，还是只能靠主观感觉？
4. 失败能否归因到具体步骤、规则、工具或权限？
5. 人工修正能否结构化，进入下一轮评测？
6. 客户上线以后，是否仍需要监控、复测与治理？
7. 可复用的是方法和结构，还是依赖复制客户原始内容？
8. 换模型、换供应商、换工具后，能力还能否迁移？

> [!question] 如果前六个问题答不清
> 先别急着谈规模。真正可持续的产品，不是把数据卖出去，而是让客户在每一次真实运行中**保留判断、发现失败，并更快变好**。
