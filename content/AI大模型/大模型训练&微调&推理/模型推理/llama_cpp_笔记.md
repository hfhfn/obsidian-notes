# llama.cpp 本地推理引擎学习笔记

> 整理自 DeepSeek 对话，结合个人理解

---

## 一、llama.cpp 是什么？

llama.cpp 是一个**底层推理引擎**，专门用于在本地设备上高效运行大语言模型（LLM）。它是 Ollama、LM Studio 等上层工具的"底座"，核心设计目标只有一个：**在一切能跑代码的设备上，把大模型的运行效率压榨到极致**。

---

## 二、与同类工具的对比

| 工具 | 核心定位 | 上手难度 | 用户界面 |
|------|----------|----------|----------|
| **llama.cpp** | 底层推理引擎 | ⭐⭐⭐ 中等 | 命令行 / Web 界面 |
| **Ollama** | 服务编排层，主打易用 | ⭐ 极低 | 命令行 + API |
| **LM Studio** | 桌面图形化工具 | ⭐ 极低 | 完整图形界面 |

> 💡 类比：llama.cpp 是**手动挡性能跑车**，更快更省油，但需要会"驾驶"；Ollama/LM Studio 是**自动挡家用车**，上手即开，但极限性能有妥协。

---

## 三、核心优势

### 3.1 运行速度与资源占用
- 推理速度**明显快于** Ollama 和 LM Studio
- 在处理 Prompt 阶段可比 Ollama **快 5–10 倍**
- 资源占用极低，甚至可在**树莓派**等低配设备上运行

### 3.2 硬件兼容性广
最新预编译版本（如 B3209）已覆盖主流硬件架构，开箱即用：

| 硬件类型 | 对应后端 |
|---------|---------|
| NVIDIA 显卡 | CUDA |
| AMD 显卡 | ROCm / HIP |
| Intel 显卡 | SYCL |
| Apple Silicon | Metal |
| 纯 CPU | CPU-only |

### 3.3 多模态支持
- 原生支持 **Qwen2.5-VL** 等视觉模型
- 能力包括：图片理解、视频分析、网页 OCR 还原、截图生成代码等

### 3.4 无审查模型支持
- 可运行 Llama 3、Gemma 2 等的**无审查（Uncensored / Abliterated）版本**
- llama.cpp 作为底层引擎**不对模型行为做任何限制**，这并非 llama.cpp 独有特性——任何能加载 GGUF 格式的工具都具备此能力

### 3.5 灵活的模型管理
- 提供可视化 **Web 界面**
- 可通过 **BAT 脚本**实现多模型一键切换（需自行编写）

## 四、性能强大的技术原因

llama.cpp 的高性能来自三个维度的深度优化：

### 4.1 激进的量化压缩
- 将模型体积压缩至原来的 **1/8 甚至更小**
- 例：28 GB 显存的 7B 模型，4-bit 量化后仅需约 **3.5 GB**
- 8-bit 量化对模型输出质量影响 **< 0.5%**

### 4.2 深度的硬件指令挖掘
- **x86（Intel/AMD）**：深度利用 AVX2、AVX-512 向量指令集
- **ARM（苹果 M 系列等）**：调用 I8MM、SMMLA 等专用矩阵乘法指令
- **NVIDIA GPU**：通过 CUDA 后端实现高效推理，支持分层卸载到 GPU
- **AMD GPU**：深度优化 RDNA 架构，MoE 模型推理性能提升高达 **4 倍**
- **苹果 Mac**：通过 Metal API 实现接近原生的推理速度

### 4.3 精细的内存与计算调度
- **分页加载 + KV 缓存分级管理**，减少内存浪费
- **NUMA 感知优化**：在多路 CPU 服务器上优化跨节点内存访问，文本生成性能提升最高 **55%**

### 4.4 性能数据速览

| 优化场景 | 技术/硬件 | 提升效果 |
|---------|---------|---------|
| AMD GPU | RDNA 架构深度优化分支 | MoE 推理提升 4× |
| ARM CPU | I8MM 指令优化内核 | 生成/处理速度显著提升 |
| x86 CPU | AMD EPYC 32 线程并行 | 7B 模型可达 280 tokens/s |
| 多路服务器 | NUMA 架构优化 | 生成性能提升 55% |
| 边缘设备 | Jetson AGX Orin | 比主流框架快 37%，内存降低 62% |
| RISC-V | Q4X 量化 + 向量化内核 | 比同类量化快约 11% |

## 五、显存与内存分配机制

这是 llama.cpp 最核心的工程设计之一：**将模型拆解，让 GPU 处理计算密集的矩阵运算，让 CPU 负责内存密集的上下文管理**。

### 5.1 模型权重：GPU 与 CPU 间的分层调度

核心参数：`-ngl` / `--n-gpu-layers`，控制将多少层 Transformer 放到 GPU 上运行。

| 目标 | 参数设置 | 实际效果 |
|-----|---------|---------|
| 极限速度（显存够） | `-ngl 999` | 全部层放入显存，最快 |
| 显存不够时自动溢出 | `-ngl -1` | **推荐默认值**，尽量填满显存，剩余自动给 CPU |
| 手动控制 GPU 占用 | `-ngl 20` / `-ngl 30` | 指定前 N 层给 GPU，适合显存紧张时微调 |
| 纯 CPU 运行 | `-ngl 0` | 不使用 GPU，速度最慢 |

> **关于 `-ngl -1` 的"准自动"逻辑：** 它并不是简单的"全放 GPU"，而是"尽最大努力利用 GPU"——显存够就全放，显存不够就自动把溢出部分分给 CPU 内存。这是日常使用最推荐的默认值。

> ⚠️ **为什么不是完全自动？** 真正实时感知硬件压力并动态调整非常复杂，容易带来性能波动。llama.cpp 选择了更可控的**静态分配**策略，在启动前确定分配方案，确保性能稳定可预测。

**实际调优流程：**```bash
# 第一步：直接拉满，看显存够不够
./llama-cli -m ./models/llama-13b.Q4_K_M.gguf -ngl 999

# 如果 OOM（显存不足），逐步降低层数直到稳定
./llama-cli -m ./models/llama-13b.Q4_K_M.gguf -ngl 30
```

### 5.2 KV 缓存：长上下文的"内存大户"

KV 缓存是推理过程中动态增长的内存，在长文本或高并发场景下往往比模型权重本身占用更多内存。

| 配置项 | 参数 | 影响说明 |
|-------|------|---------|
| 缓存量化 | `--type-k q4_0 --type-v q4_0` | F16 精度下 4096 上下文约 200MB，Q4_0 仅约 50MB，**节省 75%** |
| 上下文长度 | `--ctx-size` / `-c` | 从 2048 增至 4096，KV 缓存**翻倍**；越长越占内存 |
| 并发序列数 | `--parallel` | 单序列 F16 约 100MB，8 并发激增至约 800MB |

> 💡 **最省内存的组合**：适当缩小 `--ctx-size` + 启用 KV 缓存量化（`q4_0`），效果显著。

### 5.3 内存加载技巧

| 技术 | 参数 | 作用 | 默认状态 |
|-----|------|------|---------|
| 内存映射 | `--mmap` | 不将权重读入内存，直接"映射"磁盘文件，极大降低 RAM 占用并加快加载速度 | **默认开启** |
| 内存锁定 | `--mlock` | 将模型权重锁定在物理内存，防止被系统换页到磁盘，提升推理稳定性 | 默认关闭 |

### 5.4 动态内存与分布式扩展

- **内存状态接口（`llama_memory_i`）**：支持动态执行序列缓存的增删复制（`seq_rm`、`seq_cp`），用于实现并行解码、批处理等高级功能。
- **RPC 后端**：支持将计算任务分发到网络中其他机器，实现多机"算力聚合"，适合家庭多卡或小型集群场景。

## 六、Ollama 的显存/内存分配：更智能的自动驾驶

Ollama 基于 llama.cpp，但在内存管理上做得更"傻瓜式"：

### 6.1 核心逻辑与 llama.cpp 一致
同样是：**尽最大可能利用 GPU 显存，不够时自动溢出到 CPU 内存。** 但 Ollama 完全自动化，无需用户手动配置任何层数参数。

### 6.2 调度能力的进化

| 版本 | 关键升级 |
|-----|---------|
| v0.11.5 之前 | 依赖**估算**分配显存，容易因估算不准崩溃或浪费资源 |
| v0.11.5 | 引入新调度系统，改为**精确测量**所需内存，大幅减少 OOM；更高效支持多 GPU 协同（含混搭显卡） |
| v0.11.8 | 多 GPU 环境下自动释放未使用的显存；优化模型加载顺序，减少内存碎片 |
| v0.11.11 | 新内存估算机制作为默认功能全面开启；改进对混合架构模型的内存预估 |

### 6.3 需要手动干预时的参数

| 参数/环境变量 | 用途 |
|-------------|------|
| `--num-gpu` | 限制使用的 GPU 层数/比例，为其他程序预留显存 |
| `CUDA_VISIBLE_DEVICES` | 多卡机器上指定使用哪几张卡 |
| `OLLAMA_KEEP_ALIVE` | 控制模型常驻内存时间；设为 `-1` 可让模型永久驻留（避免重复加载等待） |

## 七、显存分配策略总结对比

| 工具 | 分配方式 | 自动化程度 | 适合场景 |
|-----|---------|-----------|---------|
| **llama.cpp** | 静态分层（`-ngl`），`-1` 可准自动 | 中等，需理解参数含义 | 追求极致性能、需要精细控制 |
| **Ollama** | 全自动，精确测量后智能分配 | 极高，开箱即用 | 日常使用、快速部署 API 服务 |
