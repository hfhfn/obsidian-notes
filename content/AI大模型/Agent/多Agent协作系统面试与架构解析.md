# 多Agent协作系统面试与架构解析

**时长**：约 6 分 12 秒

**摘要**：视频以一场大厂算法面试场景引入，模拟了一个四 Agent 协作撰写市场分析报告时频繁出错的事故，引出多 Agent 系统的核心难点。随后分层拆解了多 Agent 协作的四大深层问题（信息不一致、任务依赖混乱、幻觉级联传染、链路雪崩）以及三层应对架构（共享状态+DAG 编排+结果校验、生产级熔断降级、全链路可观测与灰度评测），帮助学习者建立从"跑得动"到"跑得稳"的多 Agent 系统思维方式。

---

## 时间轴 · 画面与讲解

### [00:00–00:10] 面试开场：还原线上事故
- **场景**：面试官给出一个多 Agent 协作失败的线上事故案例。
- **四个 Agent 角色**：
  - **规划 Agent**：拆任务
  - **调研 Agent**：查数据
  - **分析 Agent**：做推理
  - **写作 Agent**：出报告
- **事故表现**：报告内数据互相矛盾——调研 Agent 查到的市场规模是 500 亿，分析 Agent 算成了 800 亿，写作 Agent 最后写成了一两万亿，还重复生成了 3 版摘要。
- **核心提问**：这是 Agent 能力不行，还是协作架构有问题？

### [00:10–00:20] 候选人第一反应：角色定义
- 候选人愣了一下，认为是**角色定义不够清晰**，建议用 CrewAI 把每个 Agent 的 Role 和 Goal 写详细。
- **面试官追问**：角色写得再详细，4 个 Agent 仍各有各的上下文。调研 Agent 查到的数据，分析 Agent 根本没拿到，自己瞎编了一个——你告诉 Agent 之间怎么共享信息？

### [00:20–00:50] Agent 信息共享的两难
- **两难困境**（图示：左右分支结构）：
  - **全量上下文同步** → Token 爆炸（4 个 Agent 跑一轮，State 里塞了几万 token）
  - **只传结果** → 信息丢失
- 候选人提到用 LangGraph 的状态图（State Graph）做节点共享 State。
- **面试官追问**：LangGraph 的 State 是全量传递的。

### [00:50–01:10] 幻觉级联传染
- **场景**：调研 Agent 调用工具失败，返回空结果；分析 Agent 拿到空数据直接开始编造；写作 Agent 再把编造的数据写进报告。
- **关键点**：幻觉从这一层开始传染，下游全错。后面的 Agent 注意力被稀释，关键数据被淹没。
- **追问**：你怎么拦？

### [01:10–01:20] 死锁问题
- **任务 DAG 中两个 Agent 互相等对方的输出**，直接死锁，整个链路卡住。
- **追问**：怎么解？

### [01:20–01:30] 面试结束：面试挂掉
- 候选人额头冒汗，说"回去再研究研究"。
- 面试官合上笔记本。
- **结论**：两年大模型应用开发能把 CrewAI 跑通，不叫会做多 Agent。

### [01:30–01:50] 核心观点抛出
- 屏内文字：**「多 Agent 的水比你想的深，Agent 越多不是越强，是越容易乱。」**
- **破局关键**：先把信息共享和幻觉防控这两块啃透，再来面大厂。
- 视频预告：整理了涵盖大模型基础、RAG、微调、Transformer、DeepSeek、Agent、项目方案面试题等的必考题库 PDF。

### [01:50–03:00] 第一层：多 Agent 协作的四大深层死穴
> 每个死穴均有对应画面要点。

1. **信息不一致与上下文孤岛**
   - 每个 Agent 有独立的上下文窗口，调研 Agent 查到的关键数据，分析 Agent 根本看不到，只能自己脑补。
   - 全量同步上下文 → Token 爆炸、成本高；只传摘要 → 信息丢失。
   - 这是多 Agent 的物理矛盾，不是写好 Role 就能解决的。

2. **任务依赖混乱与重复劳动**
   - Agent 之间任务依赖关系复杂，规划 Agent 拆任务拆错了，两个 Agent 干同一件事，该干的事没人干。
   - DAG 依赖没定义清楚，A 等 B 的输出、B 等 A 的输入，直接死锁，整个链路卡住。

3. **幻觉级联传染**
   - 一个 Agent 输出错误信息（工具调用失败返回空、模型自己编数据、理解错任务），下游 Agent 当成事实继续推理。
   - 错误逐级放大，到最后报告里全是错的，你不知道是从哪个 Agent 开始错的。

4. **失败恢复与链路雪崩**
   - 一个 Agent 超时、工具调用失败、输出格式不对，整个协作链路就崩了。
   - 没有重试机制、没有降级策略、没有人工介入点，一次失败等于全部白干，前面几个 Agent 的 Token 全浪费了。

### [03:00–05:10] 第二层：核心方案（共享状态 + DAG 编排 + 结果校验）
> 多 Agent 不是简单拉几个 Agent 聊天，而是**共享状态空间 + DAG 任务编排 + 结果校验闭环**的三层协作架构。

#### ① 结构化共享状态 + 消息总线
- 不用全量上下文同步，也不用各搞各的。
- 建一个**结构化共享状态空间（Shared State）**，定义清楚：
  - 每个字段是什么
  - 由谁写、谁可读（如 `market_data` 字段只能由调研 Agent 写，`analysis_result` 只能由分析 Agent 写）
- Agent 之间通过**消息总线**通信，不是直接互相对话，而是把结果写入共享状态，下游 Agent 从状态里读需要的字段。
- 状态带**版本号**和**写入者 ID**，每一次变更可追溯。Token 开销可控，信息不丢失，还能防止 Agent 乱改别人的字段。

#### ② DAG 任务编排 + 角色边界
- 任务拆解用**有向无环图（DAG）**定义，每个节点是一个 Agent，边是数据依赖关系。
- DAG 由规划 Agent 生成，但必须经过**校验器**检查：
  - 有没有环
  - 有没有孤立节点
  - 有没有重复任务
- 校验通过才执行。
- 每个 Agent 的**角色边界**严格定义：
  - 输入是什么
  - 输出是什么格式
  - 能调用哪些工具
  - 不能碰哪些状态字段
- 越界操作直接拦截，不是 Agent 想干啥就干啥。

#### ③ 结果校验 + 反馈闭环
- 每个 Agent 的输出不是直接传给下游，而是先过**校验器**：
  - **格式校验**（JSON Schema）
  - **事实校验**（关键数据是否有来源支撑）
  - **一致性校验**（和共享状态里的已有数据是否矛盾）
- 校验不通过 → 打回该 Agent 重生成，附带错误原因。
- **最多重试两次**，仍不通过则**降级**（用默认值或跳过该节点）并标记告警。
- 幻觉在源头就被拦住，不会传染到下游。

### [05:10–06:12] 第三层：生产级终极防御
> 从"能跑通"到"稳得住"的关键跨越。

1. **多 Agent 一致性对账**
   - 整个协作流程结束后，做最终一致性校验。
   - 报告里的每一个关键数据、每一个结论，都要能追溯到共享状态里的对应字段和来源 Agent。
   - 对不上的标记为"无依据"，要么删除，要么标注待核实。
   - 不是生成完就交付，是生成完还要对账。

2. **熔断降级与人工介入**
   - 每个 Agent 节点设超时时间和重试次数，超过阈值自动熔断。
   - **关键节点**失败 → 触发人工介入（把当前状态和问题推给人处理）。
   - **非关键节点**失败 → 用降级策略（跳过、用默认值、简化处理）。
   - 绝不允许一个 Agent 卡住整个链路。

3. **全链路可观测与成本核算**
   - 每个 Agent 的输入、输出、Token 消耗、耗时、工具调用、重试次数全记录。
   - 整个协作流程的总成本、各 Agent 占比、瓶颈点一目了然。
   - 哪个 Agent 最费 Token、哪个最容易出错、哪个是瓶颈——用数据说话，不是感觉。

4. **灰度发布与效果评测**
   - 多 Agent 流程变更（改角色、调 DAG、换模型）必须走灰度。
   - 先跑一批标准任务集，对比输出质量、一致性、成本、耗时。
   - 建立多 Agent 评测集，覆盖简单任务、复杂任务、异常场景。
   - 每次变更跑评测，用数据验证是不是真的变好。

### [06:10–06:12] 收尾金句
> **多 Agent 的分水岭，不再会不会用 CrewAI，而是能不能从跑得动干到跑得稳。**
> - 稳得住信息一致
> - 稳得住任务流转
> - 稳得住幻觉不扩散

## 知识速查表

| 维度 | 核心要点 |
|------|---------|
| **共享状态** | Shared State + 消息总线，字段级读写权限，版本号+写入者ID可追溯 |
| **任务编排** | DAG 定义节点与依赖，规划 Agent 生成后需经校验器（无环/无孤立/无重复） |
| **角色边界** | 严格定义输入/输出/工具/可写字段，越界拦截 |
| **结果校验** | 格式（JSON Schema）→ 事实（来源支撑）→ 一致性（与共享状态比对），失败重试≤2次，再失败降级+告警 |
| **生产防御** | 一致性对账、熔断降级、人工介入、全链路可观测、灰度发布+评测集 |
| **关键认知** | Agent 越多不是越强，是越容易乱；分水岭在于从"跑得动"到"跑得稳" |
