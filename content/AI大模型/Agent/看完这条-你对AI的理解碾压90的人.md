# 看完这条：AI 七层全貌（Token → Skills）

> [!abstract] 摘要
> 从 **Token 到 Skills** 的 AI 协作全景，分七层逐层拆解：Token → 提示词 → 上下文 → Agent → Harness → MCP → Skills。
> 学习路径：**先懂 Token → 写好 Prompt → 管理 Context → 设计 Agent → 搭建 Harness → 接入 MCP → 沉淀 Skills**。
> 来源：[抖音图文](https://v.douyin.com/wUWszYAJw54/)

---

## 七层全景总览

| 层 | 核心定义 | 类比 |
|---|---|---|
| **Token** | AI 的最小输入单元 | 乐高小粒 |
| **Prompt（提示词）** | 人与 AI 对话的指令 | 点餐的菜单指令 |
| **Context（上下文）** | 多轮记忆与外部知识 | 随身记事本 |
| **Agent（智能体）** | 能自主行动的智能体 | 自动跑腿的助手 |
| **Harness（框架/编排）** | 工作流编排框架 | 任务流水线 |
| **MCP（模型上下文协议）** | 模型上下文协议/工具标准 | 通用翻译手册 |
| **Skills（技能）** | 可复用技能包装 | 随身工具包 |

> [!tip] 记忆口诀：**「Token是砖，Prompt是图，Context是地」**。

## 1. Token —— AI 理解世界的最小积木

![[AI大模型/Agent/看完这条-你对AI的理解碾压90的人_图文/img_03.webp]]

- **核心作用**：大模型处理文字的基本单位；英文按子词（subword）、中文常按字/词切分。
- **换算**：`1 token ≈ 0.75 个英文单词`、`1-2 个汉字`。
- **控制技巧**：精简表达、删除冗余、用英文关键词更省 token、合理分段。
- **常见误区**：不是按字符数计费；不是一个词一定等于一个 token。
- **实战**：“人工智能”≈2-4 tokens，“AI”≈1 token。

---

## 2. Prompt（提示词）—— 让 AI 听懂的人话翻译器

![[AI大模型/Agent/看完这条-你对AI的理解碾压90的人_图文/img_04.webp]]

- **核心作用**：人与大模型的唯一沟通接口，提示词质量直接决定输出质量。
- **万能结构**：`角色(Role) + 任务(Task) + 背景(Context) + 约束(Constraint) + 输出格式(Format) + 示例(Example)`。
- **关键要素**：角色设定（明确身份）、任务描述（具体可执行、避免模糊动词）、约束条件（长度/风格/禁止项/引用来源）、Few-shot 示例（2-3 个输入输出样例）。
- **进阶技巧**：使用分隔符 `##`、让 AI 先思考再回答、要求自我检查、链式提示拆解复杂任务。
- **常见误区**：提示词不是越长越好；不要一次提多个矛盾要求。
- **模板**：`你是一位XX，请根据YY，完成ZZ，要求AA，输出BB格式`。

---

## 3. Context（上下文）—— AI 的记忆库与知识外挂

![[AI大模型/Agent/看完这条-你对AI的理解碾压90的人_图文/img_05.webp]]

- **核心作用**：为模型提供当前任务所需背景，决定回答是否精准、连贯。
- **上下文窗口**：模型一次能处理的 token 上限，包含系统提示 + 历史对话 + 当前输入。
- **多轮记忆**：短期记忆在窗口内，超出会被截断或压缩。
- **长期记忆方案**：向量数据库、知识库、RAG 检索增强生成、外部笔记/文档。
- **RAG 流程**：用户想问 → 向量化 → 检索相关片段 → 拼接进 Prompt → 生成答案。
- **管理技巧**：保留关键信息、删除无关历史、使用摘要压缩、分块输入。
- **常见误区**：以为 AI 能记住很久以前的话；把所有资料一次性塞进去。
- **优化口诀**：**「相关、精简、结构化、可追溯」**。

---

## 4. Agent（智能体）—— 能自主行动的数字员工

![[AI大模型/Agent/看完这条-你对AI的理解碾压90的人_图文/img_06.webp]]

- **核心作用**：以大模型为大脑，能感知环境、做决策、调用工具、完成多步骤任务。
- **关键能力**：规划 Planning、推理 Reasoning、工具调用 Tool Use、记忆 Memory、反思 Reflection、行动、围绕一个 Action。
- **ReAct 模式**：`Thought（思考）→ Action（行动）→ Observation（观察）` 循环。
- **Multi-Agent**：多个 Agent 分工协作（规划者、执行者、检查者、专家）。
- **应用场景**：自动写报告、代码生成与调试、数据采集、客户服务、研究助手。
- **设计要点**：明确目标、定义工具、设置停止条件、容错机制。
- **与 Chatbot 的区别**：Chatbot 只回答问题；Agent 能自主做事。

> [!tip] 一句话：**Prompt 是给 AI 下命令，Agent 是让 AI 自己去干活**。

---

## 5. Harness（工作流编排框架）—— 把 AI 能力组装成流水线

![[AI大模型/Agent/看完这条-你对AI的理解碾压90的人_图文/img_07.webp]]

- **核心作用**：框架/平台，将 Prompt、模型、工具、Agent 组合成**可复用、可观测**的工作流。
- **核心组件**：节点 Node、边/连接 Edge、变量 Variable、条件分支 Condition、循环 Loop、人机确认 Human-in-the-loop。
- **常见框架**：LangChain、LlamaIndex、Dify、Coze、FastGPT、Flowise、AutoGen。
- **能力**：提示模板管理（集中管理 Prompt 版本、AB 测试、动态注入）、可视化编排（低开发门槛）、评估与监控（输入输出记录、效果评分、错误追踪、成本统计）。
- **应用场景**：智能客服、内容生产流水线、审批助手、数据分析报告、营销自动化。
- **选型建议**：个人试用 Coze/Dify；企业级用 LangChain/LlamaIndex + 自建。

> [!tip] **Harness 是「舞台和剧本」，Agent 是「演员」**。Harness 让 AI 从单点能力变成系统能力。

---

## 6. MCP（模型上下文协议）—— AI 与外部世界的通用插座

![[AI大模型/Agent/看完这条-你对AI的理解碾压90的人_图文/img_08.webp]]

- **核心作用**：Anthropic 提出的开放协议，统一大模型与外部数据源、工具的连接方式。
- **架构组成**：`MCP Host`（如 Claude Desktop/IDE）+ `MCP Client` + `MCP Server`（提供资源/工具/提示）。
- **三大能力**：Resources（语义资源）、Tools（可执行工具）、Prompts（预定义提示模板）。
- **工作方式**：Server 注册能力 → Client 发现工具 → 模型决定调用 → 执行后返回结果。
- **与 Function Calling 区别**：Function Calling 是**模型能力**；MCP 是**工具供给标准**。
- **开发优势**：一次接入、多客户端复用，降低工具集成成本（像 USB-C/HTTP，让不同 AI 应用共享同一套工具生态）。
- **热⻔ Server**：文件系统、GitHub、数据库、Slack、浏览器、知识库、日历。

> [!tip] 一句话：**MCP 让工具像 App 一样即插即用**。

---

## 7. Skills（技能）—— 可复用、即拿即用的积木

![[AI大模型/Agent/看完这条-你对AI的理解碾压90的人_图文/img_09.webp]]

- **核心作用**：将特定任务的 AI 能力（Prompt + 工具 + 工作流）打包成可复用、可分享、可交易的模块。
- **技能组成**：输入参数、系统提示、工具调用、输出格式、示例、错误处理。
- **与 Agent 区别**：Agent 是「能自主决策的完整员工」；Skill 是「完成单一任务的熟练手艺」。
- **创建步骤**：定义任务 → 编写 Prompt → 选配工具 → 测试迭代 → 封装发布 → 收集反馈。
- **复用价值**：避免重复造轮子、沉淀组织知识、降低使用门槛。
- **质量指标**：准确性、稳定性、易用性、可解释性、安全性。

> [!tip] 一句话：**Skills 是 AI 时代的 App，封装智慧，随手用**。
