# Agent主流架构对比与选型

本文梳理了目前7种主流的Agent架构，从轻量的原型验证方案到企业级生产环境使用的重型框架。架构没有统一标准，选型取决于场景复杂度与所需的控制力；整体演进路径为单Agent → 多Agent协作 → 基于图的Workflow，其中AI Coding方向推荐使用 Route+Skill 架构。

### 00:30–00:50 架构拆解·01/07：单Agent架构
- **流程**：用户输入 → LLM思考 → 调用工具 → 输出结果
- **典型代表**：早期 ChatGPT
- **优点**：简单、成本低、延迟低
- **任务变复杂时**：认知过载、上下文污染
- **适合场景**：简单对话验证

**画面要点**
- 功能结构示意图：带边框矩形内四模块流程式排列；右侧分块展示优缺点（绿色对勾/红色叉号图标）

---

### 00:50–01:10 架构拆解·02/07：ReAct架构
- **核心范式**：思考 → 行动 → 观察 → 结果 → 再思考（循环至完成）
- **优点**：具备完整链式推理能力，可解释性好，比单Agent更强
- **代价**：Token消耗大，不够稳定，容易跑偏，不适合大规模工程化系统

**画面要点**
- 深色幻灯片，含 `Reason` 与 `Act` 方框及"+"号，中央"思考→行动"流程框，右侧"经典Agent范式"标识

---

### 01:10–01:30 架构拆解·03/07：Plan and Execute
- **思路**：面向工程的规划执行分离——先规划生成完整步骤，再逐步落地执行
- **优点**：稳定性高，适合代码生成和长流程自动化
- **致命弱点**：计划如果错了，全盘崩溃；灵活性不如 ReAct

**画面要点**
- 分栏界面：左侧 `PLAN·规划`（步骤一~三，含勾选框）→ 箭头 → 右侧 `EXECUTE·执行`（三项均已勾选）

---

### 01:30–01:40 架构拆解·04/07：多Agent架构
- **结构**：上层任务协调与分配系统统筹，下层 Planner / Reviewer 等角色各司其职
- **最大优势**：任务拆解清晰，上下文污染小，扩展性强
- **代价**：成本高
- **适合**：对流程一致性要求高的复杂行业场景

**画面要点**
- 架构图：`任务协调分配系统` 下挂 `planner`、`reviewer`、`更多角色`，连线关联；下方标注"规划""审查"等子功能

---

### 01:40–02:10 架构拆解·05/07：Route + Skill 架构（⭐ 目前最推荐）
- **核心理念**：不让模型想——用户输入进来，过一层图识别，直接路由到对应的 Skill 去执行，配备对应知识
- **核心优势**
  - 稳定性极强
  - 企业级可控
  - 可缓存，性能高
  - 易评估命中率（示例显示 92%）
- **唯一代价**：Skill 设计成本高，可能出现路由冲突
- **应用现状**：目前 AI Coding 领域和智能系统的主流方案

**画面要点**
- 深色界面分两栏：左栏"核心优势"四项（盾牌/齿轮/杯子/圆圈勾选图标），右栏"唯一代价"含折线图与按钮

---

### 02:10–02:20 架构拆解·06/07：Blackboard（黑板）系统
- **思路**：多 Agent 同时读写共享状态，由状态变化驱动执行
- **适用场景**：复杂协作场景
- **代价**：状态管理很重，问题不好追踪
- **典型应用**：工作流引擎和分布式系统常用此思路

**画面要点**
- 架构图：中央 `共享状态` 方框，周围环绕 `AGENT 1~4`，箭头双向连接，下方标注"状态变化·驱动执行"

---

### 02:20–02:40 架构拆解·07/07：Graph Workflow（基于图的有向无环图编排）
- **定位**：企业级生产环境最重但也最稳的一套
- **能力**：支持条件分支、并行执行、可回溯、可重试
- **代表工具**：LangGraph、Temporal、n8n、Prefect
- **优势**：企业级稳定、可 Debug、支持长流程
- **适合**：流程自动化与生产环境

**画面要点**
- 深色科技风界面，展示 DAG 工作流：`START` → `条件` → `任务A/B` → `汇聚` → `输出`，节点间带标签箭头；右上角图例标注"重量级 MAX""稳定性 MAX"

---

### 02:40–02:50 总结：架构演进线与选型建议
- **演进线（复杂度逐级递增）**：
  单Agent（简单验证）→ ReAct（多步探索）→ Plan-Exec（工程化）→ 多Agent（协作）→ Route+Skill（精准技能系统）→ Blackboard → Graph Workflow
- **一句总结**：架构只有最合适的架构，根据场景复杂度选对应档位即可。

**画面要点**
- 阶梯式演进示意图：多级矩形框标注各架构名称，上升趋势折线贯穿，右侧文字汇总演进逻辑
