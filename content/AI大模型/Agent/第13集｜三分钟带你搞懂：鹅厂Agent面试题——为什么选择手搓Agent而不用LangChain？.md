# 第13集｜鹅厂Agent面试题——为什么选择手搓Agent而不用LangChain？

> [!abstract] 摘要
> 面试官问「为什么选择手搓 Agent 而不用 LangChain 这类框架」，直接答「框架太重」只会出局。正确思路是围绕**过程掌控、上下文工程、交互调度**三大优势展开，并辅以 GitHub 上成熟的开源项目作佐证。框架并非无用，但在原型验证之外，**生产级 Agent 更适合手搓**。

---

## 一、核心反例：别只说「框架太重」

> 回答「框架太重」= 出门右拐等通知。要把「重」翻译成可论证的工程问题。

### LangChain 的问题一：过度封装
- 一个简单的文本生成，调用链要经过 `ChatOpenAI` 等多个类才能送达 LLM。
- 抽象越多，越难看清原始请求，**调试成本飙升**。

### LangChain 的问题二：版本变动频繁
- 最早的 `chain` 已废弃；官方推荐写法从 `create_react_agent` 变成 `create_agent`，业务逻辑没变但代码得跟着改。

> [!note] Anthropic 官方博客观点
> 框架为通用性叠加了过多抽象层，反而**隐藏了原始提示词**，建议开发者直接组织 API 与工具。

---

## 二、真实迁移案例：从 LangChain 换回手搓

- **Octomind 工程实践**：使用 LangChain 一年多，最终不得不换回手搓。
- **迁移原因**：需要在 Agent 运行过程中**动态调整可用工具**（如按任务配置搜索/读取/写入工具），而 LangChain 没有任何机制来观察或控制 Agent 的中间状态。

---

## 三、手搓的核心优势（回答主线）

### 优势一：对 ReAct 执行过程的绝对掌控
- 框架把模型调用、工具分发封装为黑盒；Agent 跑偏、吐出参数出错时，开发者根本无法插手。
- 手搓的好处：**每一步都能实时插装、拦截、动态修正**——
  - 模型每一步在想什么？
  - 调了什么工具？
  - 返回值合不合理？
- 这种**可观测性与可干预能力**是框架提供不了的。
- 以一次工具调用为例：

```text
模型输出 → 校验通过 → 调用工具（如 search，limit=-1）→ 返回结果 → 进入下一步
```

### 优势二：上下文工程与成本极致压缩
- 通用框架为兼容各种场景，常夹带大量冗余封装提示词。
- **Prompt Caching 的关键：前缀对齐**
  - 稳定内容（系统提示、工具定义）放在**靠前**，动态内容（用户问题、时间戳）放**靠后**。
  - 前缀一旦变化，服务端 Prompt Caching 频繁失效，**成本激增**。
- 手搓可以做到精致的**前缀感知与动态压缩**，有效命中缓存。

### 优势三：流式交互与并发调度
- 决定用户体验的核心不是模型本身，而是 **Harness（执行层）**。
- **流式推送**：模型推理过程中，思考过程与工具状态实时推给前端，让用户「看得到进度」。
- **并发与串行调度**：
  - 查资料、读文件等**只读操作** → 全量并发执行。
  - 写代码、跑命令等**写操作** → 严格排队串行，避免冲突。
- **超时与中断**：工具执行超时或抛异常时，能通过中断信号秒级终止。
- 这种兼顾**速度、秩序与安全**的高性能调度，框架几乎不可能提供。

---

## 四、给面试官的回答框架

1. **先肯定框架价值**：验证原型（MVP）时，框架能快速搭 Demo 跑通流程，节省时间。
2. **再说生产级选择**：Codex、Claude Code 等成熟 Agent 已经很强，手搓一个 Agent 已无实质难度；GitHub 有大量优质开源项目可直接学习。

---

## 五、五个开源项目佐证（学习路径）

| 项目 | Star | 亮点 | 学什么 |
|---|---|---|---|
| **mini-swe-agent** | 7.5k | 普林斯顿团队约 **100 行 Python** 实现完整 Agent 核心骨架，SWE-bench 高分 | Agent 最极简、最原始的核心架构 |
| **OpenAI Agents SDK** | 近 3 万 | 将 **Agent / Runner / Tool / Guardrail / Handoff** 五大能力拆解清晰 | 干净、标准的模块化 Agent 工程范式 |
| **Aider** | 逼近 5 万 | **Repo Map** 以极小代价压缩整仓为结构地图；多文件编辑支持 diff / patch / full file | 让 Agent 吃透大型项目、精准控制改写 |
| **Goose** | 5.4 万 | Block 开源的**高性能 Rust Agent**，深度集成 MCP 协议 | MCP 落地 + 系统级高并发 Agent 架构 |
| **PydanticAI** | 过 2 万 | **类型安全**体验（依赖注入、类型化工具、结构化输出） | 写类型安全、不易踩坑的生产级 Agent |

**mini-swe-agent 核心循环**（伪代码）：

```python
while not done:
    action = model(history)
    result = execute(action)
    history.append(result)
```

## 六、总结

- 若面试官追问「框架完全没用吗？」，回答：**有，主要用于原型验证阶段**。
- 一句话回答主线：**生产级 Agent 需要过程掌控、上下文工程与交互调度，框架满足不了，所以手搓。**
