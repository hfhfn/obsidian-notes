## 一、8 大架构总览

| # | 架构 | 一句话 | 标签 |
|---|------|--------|------|
| 01 | ReAct | 结合思考与行动，推理与行动协同 | 动态解决问题 |
| 02 | Plan-and-Execute | 先规划后执行，规划与执行分离 | 更稳健可靠 |
| 03 | Multi-Agent | 分工协作完成复杂任务 | 多智能体协作 |
| 04 | Reflective Agent | 反思总结优化，持续自我提升 | 反思型智能体 |
| 05 | Tool-Augmented | 调用外部工具扩展能力边界 | 工具增强型 |
| 06 | Memory-Augmented | 长短期记忆结合，上下文更强大 | 记忆增强型 |

## 二、逐架构详解

### 01 ReAct · 推理与行动协同
- **流程**：*想 → 做 → 看反馈 → 再想 → 再做*，循环到完成。
- **组成**：用户输入 / 上下文 Context+Memory → 推理 Reasoning → 决定 Decide → 行动 Action → 执行 Execute → 观察 Observation（环境与工具反馈）→ 完成 Done / 最终输出。
- **定位**：最基础的、所有架构的起点。
- **优点**：简单，啥都能套。
- **缺点**：来回调 LLM，费钱又慢。

### 02 Plan-and-Execute · 规划与执行分离
- **两阶段**：先规划（拆任务、排顺序）→ 再执行（逐个干、验证结果）。
- **流程**：用户目标 → 任务规划器（子任务分解 + 依赖分析）→ 有序子任务列表 → 执行器（工具调用 + 结果验证）→ 成功 → 聚合结果；失败则触发 Fail 重规划（退回重来）。
- **优点**：复杂任务好用，可以回滚。
- **缺点**：规划不一定是准的，小任务用这个太重了。

### 03 Multi-Agent · 多智能体协作
- **结构**：用户请求 → 协调器 Orchestrator → 多个 specialist（搜索 / 写作 / 编程 / 质检 Agent），共享知识库，最后汇总输出。
- **定位**：一个搞不定就上多个，像真人团队。
- **优点**：效率高、专业分工。
- **缺点**：协调成本高，Agent 互相"打起来"就麻烦。

### 04 Reflective Agent · 反思型智能体
- **流程**：生成 → 反思 → 找错 → 改 → 检查 → 不过再来（最多 3–5 轮）。
- **组成**：用户请求 → 自我初始化 → 自我反思 / 错误分析 / 改进策略 → 检查 Check → 通过 Pass → 最终输出；未通过则 Fail 重回。
- **定位**：自己给自己当质检员。
- **优点**：输出质量高，自我进化。
- **缺点**：烧钱之王，每轮都调一次 LLM。

### 05 Tool-Augmented · 工具增强型
- **组成**：LLM Core（Planning & Reasoning）+ 工具集：搜索 / 知识库 / 浏览器 / 代码 / 分析 / 自定义工具。
- **机制**：给大脑配上手脚。LLM 自己维护工具列表，接请求决定调用哪个，拿结果整合回复。
- **优点**：从"嘴炮"变"实干"，现代 Agent 标配。
- **缺点**：工具烂的话，啥都白搭。

### 06 Memory-Augmented · 记忆增强型
- **四级记忆**：当前会话 → 短期 → 长期 → 向量数据库（外部存储）。
- **组成**：用户交互 → LLM 处理器 → 感觉缓冲 Sensory Buffer → 处理 → 响应；短期/长期记忆 + 外部 Vector DB。
- **机制**：系统自动在层级间搬运、清理记忆。
- **优点**：不会聊两句就失忆，适合长期交互。
- **缺点**：管理复杂，用久了存储蹭蹭涨。

### 07 RAG Agent · 检索增强生成
- **流程**：用户查询 → 意图理解 → 查询改写 → 查询向量化 Embedding → 检索向量库 → 混合检索 → 结果排序 Rerank → 上下文整合 → LLM 生成 → 输出答案。
- **定位**：先查资料再回答。
- **优点**：减少幻觉，回答可溯源，知识实时更新。
- **缺点**：搜得不好就答得不好，得维护知识库。

### 08 Autonomous Loop · 自主智能体循环
- **流程**：长期目标 → 目标分解 → 任务优先级队列 → 执行任务 → 结果评估 → 记忆更新 → 进度追踪 → 拿下个任务，一直循环。
- **组成**：工具系统 / 外部感知 / 经验记忆 + 长期目标（最高优先级）。
- **定位**：真正自动驾驶，适合跑批任务。
- **缺点**：可能跑偏，得有人盯着。

## 三、Agent 基础与决策模型（补充页）

**Agent 核心决策逻辑**：LLM 根据动态变化的环境信息，执行具体行动/对结果作判断并影响环境，通过多轮迭代重复直到完成目标。
- **精确决策流程**：P（感知）→ P（规划）→ A（行动）。
  - **感知 Perception**：从环境收集信息并提取相关知识。
  - **规划 Planning**：为某一目标做出的决策过程。
  - **行动 Action**：基于环境和规划做出的动作。
- 其中 **Policy** 是做出 Action 的核心决策，行动通过观察 Observation 反哺下一轮 Perception，形成闭环。
- Agent = 环境观察 + 短/长期记忆 + 工具（计算器、代码解释器、搜索、日历…）+ 反思/自批评。

**工程实现四大核心模块**：推理、记忆、工具、行动。

**ReAct 决策模型对比**：
- 传统 ReAct = 少样本 prompt + Thought + Action + Observation（先推理再执行）。
- 变体：Reason Only（Chain-of-thought）／ ReAct（Reason+Act）／ Plan-and-Execute ReAct。
- 类 BabyAgent 流程：优化规划与执行流程完成复杂任务拆解，多次任务也只需调用三次大模型，而非每次工具调用都调。

**总结**：`Agent = 大模型 + 知识 + 工具 + 循环逻辑 + 工作流 + 评测 + 部署运维`

## 四、AI Agent 从原理到应用（讲义页）

**定义**：AI Agent（人工智能代理 / 智能体 / 智能业务助理）是一种能感知环境、进行决策并执行动作的智能实体。在大模型技术驱动下，以自然语言交互，自动执行/处理专业而繁复的工作任务，释放人员精力。本质 ≈ "大模型 + 插件 + 执行流程 / 思维链"，对应控制端（大脑 Brain）、感知端（Perception）、执行端（Action）三环节。

**大脑模块（由 LLM 组成）**：
- 存储知识与记忆，承担信息处理与决策，呈现推理与规划过程，能较好应对未知任务。
- 运行机制：接收感知模块信息 → 转内部存储 → 知识检索 → 从记忆回忆 → 决策 → 行动。

**记忆类型（映射示例）**：
- 感知记忆：短暂保留感官输入 → 例：看一张图片，图片消失后能回想视印象。
- 短期记忆：上下文学习、处理多子任务时保留短期内容 → 例：心算时记住几个数字。
- 长期记忆：语义记忆（非情绪化，陈述/情节记忆）→ 经验、语义的长期沉淀。

**典型应用项目（开源对照）**：AutoGPT、BabyAGI、SuperAGI、SmartGPT、ChatDev、MetaGPT、Camel、JARVIS、OpenAGI、XAgent 等。
